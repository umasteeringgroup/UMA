# Changelog

## 3.1f6 (package version 3.1.6)

Changes since **3.1f5 / 3.1.5** (`V3.1.5`). Unity 6.3 and newer are supported. The 3.1f5 entries below remain the record of that release.

### Installation, configuration, and validation

- **Hair Card Tests** now installs to `Assets/UMA/HairCardsTests`, beside the plugin instead of inside it, like Overlay Painter Tests. Installing Hair Card Tests again moves a copy from the old `Assets/UMA/HairCards/Editor/Tests` folder to the new one, keeping its GUIDs, before replacing it; if both folders exist, the install stops and asks you to delete the older copy. Reinstalling Hair Cards leaves the old copy in place.
- Fixed **Reinstall All Plugins** stopping at **Dismemberment Examples** with "Installed content does not match the archive: U3-GoreExample.unity" and rolling that package back. Unity's package import opens an imported scene and saves it again when it upgrades the scene's lighting settings, so the scene's bytes no longer matched the archive. The installer now accepts a scene that Unity rewrote during the import, as long as its `.meta` (GUID and import settings) still matches the archive; every other file keeps the exact byte check. The Gore example scene also ships already saved by Unity 6000.3, so it installs unchanged.
- Plugin installs and removals, and the render-pipeline (SRP) support install on the **Welcome to UMA** window, no longer stall while Unity is in the background. After each domain reload the installer resumed through `EditorApplication.delayCall`, which Unity only runs after the inspectors repaint, and an unfocused Editor does not repaint them, so **Reinstall All Plugins** paused after every package until you switched back. The SRP support install waited the same way after its import finished. Both now resume from the Editor update loop once compiling and importing finish. While install, download or removal work is running, UMA also keeps the Editor updating with Unity's internal `EditorApplication.SignalTick`; if a Unity version removes or changes that call, UMA falls back to Unity's normal background rate. A minimized or fully covered Editor window may still pause.
- **UMA > Build > Rebuild Active SRP Manifest** now warns (in the Console and in its closing dialog) about UMAMaterials whose material is missing or outside `Assets/UMA/SRP`. The manifest only lists files in that folder, so before this the problem only showed up as the "Exclude broken UMA materials?" prompt when building the package.
- Fixed the URP package build asking to exclude `UMAMaterial_UMA_SRP_DiffuseAlpha`: its material, `UMA_SRP_DiffuseAlpha_URP`, was in `Assets/UMA/ShaderPackages` and was never packaged. It now lives in `Assets/UMA/SRP/ShaderGraphs/Materials`, with the same GUID, so existing references still work.

### Recipe and character editing

- The DynamicCharacterAvatar inspector has a new **Editing tools** section, just below **Character & race** and in Standard as well as Advanced view, with the editors that used to be under **Utilities** at the bottom of Advanced view: **Open Vertex Editor (Sculpt, Paint, Mesh Modifiers)** (was **Create New Mesh Modifier**), **Open Face Editor (Mesh Hide Assets)** (was **Create New Mesh Hide Asset**), **Touchup Weights**, **Create Slot From Scene Mesh**, and the drop box for editing an existing Mesh Modifier, Mesh Hide Asset or Mesh Hide Collection. Each button says what its editor does, and the section's Help describes them in full. The section folds away, and remembers whether it is open. With **Editor Time Generation** off the section stays visible, says why its buttons are disabled, and has a button to turn it on.
- Reorganized the DynamicCharacterAvatar inspector's **Advanced View** into foldable panels grouped by job, like Standard View's sections: **Character & race** (with User Information and the race change options), **Editing tools**, **Wardrobe** (with Additional Utility Recipes and the current wardrobe), **Colors**, **Body shape & DNA** (with blendshape loading), **Animation**, **Generation**, **Build behaviour**, **Performance & sharing**, **Rendering**, **Bounds**, **Addressables**, **Events**, **Diagnostics** (Loop Build, cache diagnostics, manual Mesh Modifiers, UMA Data, the placeholder model) and **Legacy Load/Save**. The long **Advanced Options** list, the **Customization** box and the **Utilities** foldout are gone; their settings are in those panels. The global **Show Help** toggle, which put a help box above every field, is replaced by each panel's **Help**, which describes all of its settings; the Events panel no longer shows a help box above every event. The first five panels start open and the rest folded, and each remembers whether it is open as an editor preference, never on the avatar. Current Wardrobe and the manual Mesh Modifiers stay in place when the character is not built and say what is needed. Standard View is unchanged. Inspector sections can now fold (`UMAInspectorView.CollapsibleSection`).
- Added **Assets > UMA > Manage Color Parameters** for selected Shared Color Tables. It adds a shader parameter to every color, or updates it where a color already has one. The value is either fixed, or each color's own value of a parameter multiplied by a number (for example `_SpecularMultiplier` x 1.2). Colors without the source parameter can take the material's value (what they showed until now), the fixed value, or be skipped. Parameters are picked from a material, which is remembered per project in `UserSettings`. A preview lists every color's old and new value; Apply supports Undo, removes duplicate entries of the parameter, and saves only the changed tables.

### Mesh, pose, and texture authoring

- Added **Hair Root to Tip** to the Vertex Editor (in Vertex Paint and in Define Vertex Set/State), which sets a hair slot's vertex colors from black where each card grows from the head to white at its tip, as the hair sway reads them. **Recalculate Vertex Colors from Head** finds every card's root on the ticked **Head Slots** (found by name, head, face or scalp, or else as the slots the hair lies on; a UMA 3 head is two body UDIM tiles) and walks the card to its far end, so the gradient follows the card when it curves and is even across its width. A card is rooted where one of its ends goes into the head; a card that only touches the head in its middle or does not go in at all is rooted at the end clearly nearer the head, and when both ends are about as near, by **Unclear Cards** (default **Texture Top**: the root is at the top of the hair texture). On the UMA 3 hair slots this agrees with the hand-made colors on all but 0 to 6 percent of the cards; the result says how many cards each rule decided. To fix a card by hand, select its root vertices and press **Set Root**, select its tip vertices and press **Set Tip**, and press **Interpolate Colors from Root to Tip**; root marks show black and tip marks white. A new **Vertex Colors** display option draws the model with its vertex colors only, from both sides, so the gradient can be checked in any tool. The colors are saved like vertex paint: **Save as MeshModifier**, or **Save Colors to SlotDataAsset** in the section. See [Hair Animation: An Artist's Guide](Docs/HairAnimation.md).
- The Vertex Editor's **Paint** brush now paints the brush color, so white lightens as well as black darkens. Before, it always multiplied the color under the brush by the brush color, which can only darken. The old behaviour is the new **Blend > Multiply** option in the Brush section; **Replace** is the default.
- Reworked the Vertex Editor's **Noise** brush. **Noise Type** chooses **Per Vertex** grain or **Smooth** patches whose size **Noise Scale** sets; **Color Noise** varies red, green and blue separately instead of brightness only; **Noise Amount** is how far a vertex may move toward black or white. Each stroke gets a new random pattern unless **Same Pattern Each Stroke** is on, which uses **Noise Seed** every time. Noise never changes alpha. **Whole-Slot Operations** gained **Fill Slot with White**, which sets every vertex color of one soloed slot to white; the toolbar's **Clear** still restores the original colors.
- Soloing a slot (**S**) in the Slots panel of the Vertex Editor or the Face Editor now frames that slot in the Scene view, as the **Frame** buttons do, after showing it if it was hidden.
- The Vertex Editor's side panel now has the same solid background as the Face Editor's panels. It was drawn with the editor's help box alone, which is too transparent over the scene; both stages now share one panel background.
- The slot preview's "canonical matrix mismatches" warning (`SlotDataAsset.TryGetCanonicalMeshFromRootMatrix`, also used by Overlay Painter's mesh reconstruction) now only counts bones that carry skin weight. Weightless bones cannot change the result; most of them were the "_end" leaf bones exporters add with blank bind poses, which made 42 of the UMA 3 wearables, including every hair slot, warn on every preview. The warning now appears only for the 6 slots whose weighted bones really disagree with their stored skeleton (the male hoodies, the Hive jacket, the yellow tank top and the white T-shirt, all on the arms). The transform chosen for the preview is unchanged. A slot without any skin weights is checked as before.
- Fixed the stored rest skeleton of six UMA 3 tops: **LeftArm** and **RightArm**, and 14 face and leg bones (`male_hoodie_blue`, `male_hoodie_blueWhite`, `male_hoodie_grey`, `male_jacket_hive`, `male_tanktop_yellow`, `male_tshirt_white`). The arms were 44.6 degrees off the body's (an A-pose), and the eye, eyebrow and nose bones were moved by about half a centimeter, the upper lids turned 9 degrees and the nose base 5.5 degrees, although their bind poses matched the body. Every stored bone now matches the UMA 3 body. Characters were not affected in normal use: the default combiners keep the body's copy of a shared bone, and the bone baking combiners reset every body bone to the race's T-pose; only a character with a Raw Avatar, which skips that reset, could have picked up the tops' copies. Their meshes, bind poses and weights are unchanged, and no slot now logs the canonical matrix warning.
- Added **Slot Rig Conversion**, a runtime converter (`UMASlotRigConverter`) that re-targets a slot from one race's rig to another, so UMA 2 clothing can be worn by UMA 3 characters. Each vertex is baked to avatar space through its own bind poses (slots with several bind poses per bone convert exactly), optionally corrected per bone for the target body's joints and bone directions, and rebound against the target race's rest skeleton; normals, tangents, blend shapes and bone weights follow. Per-bone overrides live in a Rig Conversion Profile asset. **UMA > Tools > Slot Tools > Convert Slots To Another Rig** saves converted slots as new assets. A race can name the older rig it replaces (**Legacy Rig**); slots flagged legacy that were built for that rig are then converted automatically when a character is built. HumanMale30 is set up for the UMA 2 HumanMale rig. The **Rig Profile Editor** (button on the race, or **UMA > Tools > Slot Tools > Rig Profile Editor**) edits a profile against a live preview character: pick bones from the skeleton tree with name filters and starred favourites, adjust them with numeric fields or Move, Rotate and Scale handles in the Scene view, mirror edits to the opposite side, and watch the converted slots rebuild. Profile entries gained a scale offset and can carry their offsets down to child bones. The editor can also create Mesh Hide Assets for the previewed recipes automatically, from the body triangles each recipe's clothing covers, and add them to the recipe. A profile can hold entries for single slots as well: for that slot they replace the general entry bone by bone, and the editor's **Edit bone entries for** switch chooses between all slots and one slot. Profiles also take **effectors**: spheres and capsules, placed from a bone, that reshape whatever part of a converted slot falls inside them with a soft falloff (a capsule's strength can follow a curve along its length). An effector can push out, move, scale, or **clear the body**, which brings cloth lying under the skin out to a set clearance and so fits, for example, the seat of UMA 2 pants to the UMA 3 body without touching the front. An effector acts on every converted slot that passes through it, so a profile can be reused across a wardrobe, or is kept to one slot with its **Affects** setting; the editor lists which previewed slots have vertices inside it, warns when the slot it is kept to has none, and can mark the vertices the selected effector holds with dots in the Scene view. Hidden triangles are marked in red on the preview character and a small brush corrects them; painted triangles are stored as never-hide and always-hide marks that the generator applies after its own pass, so they survive regeneration, and a hide can be locked so the generator leaves it alone or opened in the Face Editor from the list. See [Slot Rig Conversion](Docs/SlotRigConversion.md) and [Mesh Hide Assets](Docs/MeshHideAssets.md#creating-mesh-hides-automatically).
- Sculpt mode in the Mesh Modifier editor can now **edit an existing blendshape**: **Edit Blendshape** shows the character with the shape fully dialled in, and **Save to '\<name\>'** adds the strokes to that shape on every slot they touched (all frames, with normal and tangent deltas worked out again). The Blendshape Transfer dialog opens it with **Sculpt '\<shape\>'**, on a temporary character wearing the target slots, with the previewed shape loaded and nothing written until it is saved there. See [Sculpting Mesh Modifiers](Docs/MeshModifierSculpting.md#edit-an-existing-blendshape).
- Fixed the Mesh Modifier editor leaving its panels drawn over the main Scene view, Unity's transform tools hidden and a preview scene behind when an error interrupted its closing (it happened for a character built from code, whose update event did not exist yet). Closing now always finishes.
- Added **Constant Application** to the Sculpt brush options, with an **Every (ms)** interval (default 100 ms): while the mouse button is held the brush is applied again at that interval, so its effect builds up without moving the pointer. It covers the brushes that work under the pointer and the mask brushes; the anchored drag tools are unaffected, a press is still one Undo step, and with the option off the brushes behave as before. See [Sculpting Mesh Modifiers](Docs/MeshModifierSculpting.md#constant-application).
- Fixed **Save slot modifications to base slot** and **Save slot modifications to a new slot** the same way as Save Sculpt as Blendshape below: the sculpt is taken back through the character's skinning into the slot's mesh space, vertices and normals both. Saving to the base slot now writes to the slot's asset in the project (the base slot behind a race-baked copy, the original behind a slot worn through legacy rig conversion, where it used to change only a temporary copy) and names that asset in its warning.
- Fixed Undo in the Mesh Modifier editing stage undoing every sculpt stroke at once, and ending a blendshape edit. Every Undo or Redo rebuilt the character, which replaced the sculpted mesh. The character is now rebuilt only when the step changed a Mesh Modifier, a vertex adjustment or the kind of build (normal, T-pose, reset); a sculpt, mask or paint stroke is undone on its own. The Scene view now shows the restored mesh straight after Undo or Redo; the data was put back but the picture was not redrawn from it. Redo of **Rebuild to T-Pose** and **Reset Build** now repeats that build.
- Fixed the temporary character opened by **Sculpt '\<shape\>'** in Transfer Blend Shapes losing the slots being sculpted when its recipe was rebuilt, for example by **Rebuild to T-Pose** or applying vertex weights to a slot.
- Fixed the Mesh Modifier editing stage drawing every mesh white. The editor's pastel materials set a colour property the default UMA diffuse shader no longer has; each material now gets its pastel colour again.
- The Mesh Modifier editing stage now draws its wireframe on the editable slots only, and no longer on read-only slots. It follows the Slots panel and the mesh as it is sculpted. A **Wireframe** toggle under **Original Materials** shows or hides it and is remembered. The stage opens the Scene view in Shaded mode; the Scene view's Shaded Wireframe mode still draws wires on everything.
- Added a **Heal** sculpt brush, with **Heal Masked** and **Heal Unmasked** buttons that solve a whole area in one step. Heal evens out how far vertices have been moved (the blendshape while one is being edited, otherwise the sculpt), so a pinched, folded or stretched patch returns to its modelled shape and vertex spacing, carried along with its surroundings. Use it to repair spots a blendshape transfer fitted badly.
- Touchup Weights has a **Pose Mode** and draws the skeleton. Click a bone in the Scene view and turn it with rotation rings or the Turn X/Y/Z sliders, optionally mirrored left/right, then paint weights in that pose; the mesh is skinned again as bones turn, with the weights being edited. **Show Bones** draws the skeleton in Select and Paint modes too, and **Slot Bones Only** limits it to the bones the slot uses. The pose is not saved and the character gets its own pose back when Touchup Weights closes.
- Touchup Weights has a **Weight Colors** option for the Blender-style weight coloring of the slot being weighted (red, yellow, green, blue from full weight to none). It is on by default and remembered; off shows the slot with its own material.
- Touchup Weights treats vertices of the slot that are at the same position and have the same weights as one vertex: selecting one selects them all, painting or smoothing one gives them all the same result, and they smooth against the neighbors of every copy. Painting no longer tears a mesh open along its UV, normal and material splits. Vertices at one position with different weights stay separate.
- The **Smooth** paint brush in Touchup Weights has **Constant Application** with an **Every (ms)** interval (default 100 ms): while the mouse button is held the brush is applied again at that interval, so weights keep evening out without moving the pointer. Off by default; the whole press is one Undo step.
- The temporary character opened by **Sculpt '\<shape\>'** in Transfer Blend Shapes now stands in the pose its slots were modelled in, as the transfer preview draws them. It is generated without the T-pose asset's stored human pose, which Unity's humanoid system applies with its own spread of limb twist (thighs rolled 23 degrees on Human Female 3.0), and the bones the T-pose turns are turned back. Clothing weighted to both legs was folded in the sculpt view although the slot and the transferred shape were fine.
- Fixed **Save Sculpt as Blendshape** storing sculpt movement in the character's space instead of the slot's mesh space. Where the two differ (the UMA 3 races store their meshes turned 90° from the character, and DNA scales bones) the saved shape moved vertices in another direction or by another amount than was sculpted. Movement is now taken back through the character's skinning, tangent deltas are written, and the shape goes to the slot's project asset: the base slot behind a race-baked copy, and the original slot behind one worn through legacy rig conversion, which could not be saved before.
- Added **Transfer Blend Shapes** (**UMA > Tools > Slot Tools > Transfer Blend Shapes**, or right-click slots or recipes > **UMA > Transfer Blend Shapes To Selection**), a dialog that gives any number of slots the blendshapes of a race's body so clothing follows the body. Each vertex follows the nearest point of the body surface (optionally turning with it), the movement fades with distance, is smoothed over the slot, kept clear of the moved body, and is written with matching normal and tangent deltas; seams stay closed and small parts can be kept rigid. Slots built for the race's legacy rig are matched as characters wear them, and their shapes survive automatic conversion exactly. A Scene view preview shows any shape at any weight, with movement, influence and poke-through colouring, and updates while settings change. Shapes can be written to the slots or to copies, and removed again. See [Blendshape Transfer](Docs/BlendshapeTransfer.md).
- In the Dynamic Character Avatar inspector, a race using the new DNA system now shows a **Rig Profile** button in place of **DNA Cvts**. It opens the race's Legacy Rig Profile in the Rig Profile Editor, and is greyed out when the race has none. Legacy races keep the **DNA Cvts** button.

A folder's **Edit** button loads its recipes into the preview's recipe list, replacing what is there, and **Previous** / **Next** load the neighbouring folders; the list can be filtered by path and kept to the race's recipes (including its legacy race's). The recipe list gained a **Clear** button and an **Inspect** button per recipe, which opens it in a popup Inspector.
- The Rig Profile Editor now scrolls vertically, so its lower controls (the selected bone's offsets, Reset and Remove entry) stay reachable in a short window. The bone tree is sized to its rows, up to most of the window's height, and scrolls its own rows beyond that.

- Added **Convert Legacy Content** (**UMA > Tools > Slot Tools > Convert Legacy Content**, or right-click a folder > **UMA > Convert Legacy Content In Folder**), which brings a folder of UMA 2 wardrobe recipes to the UMA 3 races. For each legacy race it creates Mesh Hide Assets on the UMA 3 body that cover the same areas as the legacy body slots (found by converting the legacy body to the new rig and taking the nearest legacy slot for every triangle), saves them inside the content folder, and adds them to each recipe that hid those slots. It also adds the UMA 3 race to the recipes and removes retired races such as `HumanMaleDCS`. Preview lists the changes first. See [Slot Rig Conversion](Docs/SlotRigConversion.md#converting-a-folder-of-legacy-recipes).

Tools, brush shapes and actions moved to a floating, movable icon toolbar beside the panels, with a **Tool** row in the panel describing the active tool. A shared **Slots** panel with **Show** and **Edit** columns, solo, and **All / None / Invert / No Base** actions replaces the per-tool slot pickers. Brush radii are shown in millimeters on the model, and save buttons stay visible at the bottom of the panel. Weight Touchup keeps its existing controls. See [Mesh Hide Assets](Docs/MeshHideAssets.md), [Mesh Modifiers](Docs/MeshModifiers.md) and [Sculpting Mesh Modifiers](Docs/MeshModifierSculpting.md).

### Generation, animation, and physics

- Fixed characters built with the bone baking mesh combiners rendering much more slowly than other combiners when **Mark Dynamic** was on. Bone baking kept the mesh that renderer creation had marked dynamic, which is slow to render with GPU skinning; it now always fills a mesh of its own. **Mark Dynamic** is off in the sample character prefabs and in the Car, Timeline, and Photobooth sample scenes, and its help text states what it does.
- Sped up the Burst normal and tangent recalculation used by **Recalculate Normals** on a UMA Renderer Asset, `RecalculationSlot`, and slot baking with a smoothing angle: about five times faster on a 40,000-vertex character in the Editor. Each vertex position is now smoothed once instead of once per triangle corner. The result is also the same on every run: tangents no longer lose additions between threads, and a vertex whose own triangles fold past the smoothing angle always uses its first triangle as the reference. A small number of normals and tangents on such folds can therefore differ from earlier builds.
- **Recalculate Normals** no longer runs when it would write the same values again. The step now keeps a fingerprint of the mesh data and blendshape weights it used, and skips a build that changed neither, such as a texture-only rebuild or a rig update that moves no participating blendshape. On a 40,000-vertex character in the Editor a texture-only rebuild went from 29 ms to 16 ms and a rig-only rebuild from 13 ms to 6 ms. It also reads and writes the mesh without managed arrays, which removes about 2.8 MB of garbage per build, and no longer rewrites the UVs. `RecalculationSlot` uses the same code. A mesh without UVs gets normals only, and a mesh that has UVs but no tangent stream gets one.
- **Reuse Identical Meshes** now also helps renderers that use **Recalculate Normals**. Their meshes are still never shared with other avatars, but with the jobified combiner an avatar keeps its own mesh when a rebuild would produce the same one, and only the normals are recalculated if blendshape weights changed. Anything that changes the combined mesh, including a direct edit of the generated mesh, combines it again. The mesh reuse key now includes a slot's `expandAlongNormal`, which the combiners read but the key had left out. See [Atlas and mesh reuse](Docs/AtlasAndMeshReuse.md).
- Sped up filling an empty skeleton in the jobified and incremental mesh paths. The second time the same set of bones is requested, a hidden copy of that hierarchy is kept, and later skeletons are made by instantiating it: 15.8 ms to 5.4 ms for 228 bones in the Editor. This applies to a character's first build and to every recipe change with **Always Rebuild Skeleton**. Bone names, components, parents, sibling order and local transforms are the same as before; unusual input falls back to creating bones one at a time. At most eight hierarchies are kept, and they are released on script reload and when entering or leaving Play mode.
- A rig update keeps its humanoid Avatar when building it again would give the same one, which is the case whenever DNA has not changed (a colour or wardrobe change, for example). The Avatar is kept only when everything it is built from is identical: the same bone objects and parents, every bone's local position, rotation and scale bit for bit, and the same human description from the T-pose asset. The stored human pose is then applied through the kept Avatar with the same call a rebuild uses, so the bones end up exactly where a rebuild leaves them. On a 229-bone character the rig stage went from 5.2 ms to 2.7 ms with the Editor in the background (1.9 ms to 0.9 ms focused). **Keep Avatar** is unchanged and still skips the step without comparing. Generic races and bone-baking skeletons always rebuild as before.
- Reduced blendshape and mesh-hide work in the jobified combiner. Blendshape frames share one set of buffers and clear only what the previous frame wrote, and a triangle mask is converted and counted in one pass.
- Cloth now behaves the same with every mesh combiner. A renderer gets a Unity `Cloth` component when its slots carry cloth coefficients (copied from a `Cloth` component on the source mesh when the slot was built). The UMA Renderer Asset's **Cloth Properties** only tune that cloth; without them it runs on Unity's default Cloth settings. Before, the default combiner's standard path removed such cloth when the renderer had no Cloth Properties and added cloth to the whole renderer when it had Cloth Properties but no coefficients, and its MeshAPI path threw a `NullReferenceException` after adding the cloth. To remove cloth from a slot, clear all of its **Cloth Skinning Serialized** entries.
- Added **Disable Hair Control at LOD** to `UMASimpleLOD` (Runtime feature reduction; -1, the default, leaves it unmanaged). At and beyond that LOD zone the **UMA > Hair Control** components on the character and below it are disabled, which stops the sway, sends the hair volume shading back to the renderer bounds, and gives the hair renderers back to the SRP Batcher; coming closer enables them again with the hair at rest, and a rebuild applies the current zone again. See [UMASimpleLOD](Docs/UMASimpleLOD.md).
- The random-character sample's timing overlay is now the **UMA Timing Overlay** object in that scene (component **UMA > Timing Overlay**), so it does not depend on where the UMA folder is installed, and it draws its text with Unity's built-in font, so it needs no font file in the project. It is compiled into its own `UMA.Timing` assembly (referencing `UMA_Core`), so a Package Manager install of UMA Core adds no script to the project's `Assembly-CSharp`.

### Shading, content, and documentation

- Fixed a visible line between the face and scalp, and at the neck, shoulders and hips, on dark-skinned UMA 3 characters. The tint protection masks (`UMA_3_BodyOnly_SkinMask.1001`–`1005`, `UMA_3_SkinMask.1002`) did not agree where the body's texture tiles meet: the face mask protected about a third more of the untinted albedo than the scalp mask along the hairline, so under a dark Skin Tint the face side rendered up to about 20% lighter. The masks now match along every seam, with the correction fading out over about 128 pixels; the rest of each mask, including the lighter palms, soles and face, is unchanged. Light tints were not affected.
- Retuned the hair colors in `SRP/Colors` (`HairColors`, `HairColors_Human`, `HairColors_Elf`, `HairColors_Orc`, `SimpleHair`) for the UMA 3 hair shader:
  - **Every hair color now sets the full highlight:** Specular Tint, Specular Strength, Anisotropic Mix, Anisotropic Smoothness and Smoothness. Before, most colors set none of these, so they took whatever the hair materials held. The two hair passes hold different tints, the second a saturated orange, which put an orange sheen on Brown, Red, Auburn and Blonde.
  - **Dark hair gets a near-neutral, high-contrast highlight; lighter hair a broader one in its own hue.** Base, root and tip colors were brought to natural values for each name: darker roots, lighter tips, a golden Blonde, a copper Red, and a mid Gray distinct from a cream Platinum.
  - **A color with the same name has the same base, root and tip colors in every table.** Race shows in the strand instead: elves have a silkier, slightly brighter highlight and half-orcs a coarser, duller one.
  - **Black in `HairColors` is unchanged and was the reference for the rest.**
  - **`SimpleHair` (URP Lit single-pass hair) uses the same base colors and now sets Smoothness per color.** A stray additive grey was removed from its Auburn.
- The Documentation Browser has a **Sort** button that puts the documents in A–Z order. Favorites stay at the top and are sorted among themselves; **Undo** restores the previous order.
- Removed low-value tests: benchmarks and profiling runs that only logged timings, preset contact-sheet captures that checked nothing, and two warm-lookup time limits that depended on machine speed. The documents that cited them now say so.
- Added **Realistic Skin SSS** (`UMA/URP/Realistic Skin SSS`, `UMA3SkinRealisticSSS.shader`), a higher quality, opt-in version of the URP Realistic Skin shader with subsurface scattering. It reads the same textures and every property of Realistic Skin, so an existing Realistic Skin material can simply be switched to it; **Assets > UMA > Skin > Create Realistic SSS URP Copy** makes a copy from a UMA 3 URP skin Material or UMAMaterial, and `Examples/UMA3_SkinRealisticSSS_Natural` is a ready Material/UMAMaterial pair. The **Natural** and **Matte** Realistic Skin examples now use the SSS shader too (Natural shares the SSS Natural material); **Dewy** stays on Realistic Skin. Diffuse light follows a measured (normalized Burley) diffusion profile per color channel, pre-integrated over curved surfaces into `UMA3SkinScatterLUT.exr` (rebuilt with **UMA > Build > Rebuild Skin Scatter Lookup Texture**; without it the shader falls back to wrap lighting). Wrinkles soften in diffuse light but stay sharp in reflections, shadow edges turn red, backlit thin parts transmit light through the thickness measured in the light's shadow map, reflections use full GGX with reflection occlusion, and occlusion is colored. New controls: **Curvature Response**, **Wrinkle Softening in Diffuse Lighting**, **Shadow Edge Scattering**, **Occlusion Color Bleed**, **Minimum Thickness in Millimeters**, and extra **View** modes. It costs more per pixel than Realistic Skin (three more normal-map reads, and shadow-map reads for transmission; set **Backlight Transmission Strength** to 0 to skip those). See the [skin shader README](SRP/Shaders/Skin/README.md#realistic-skin-sss).
- Added **Volume Shading** to the URP hair shader (`UMA3_HairShader_URP`), off by default. **Recalculate Normals** points each card's normal out from the mesh center (the middle of the renderer bounds plus **Center Offset**, object space), so layered cards shade as one volume instead of as separate flat cards; **Recalculated Normal Blend** mixes it with the mesh normal, and both faces of a card then share that normal. **Center Darkening** darkens cards near the center, which lie under other cards, between **Center Darkening Start** and **End** (distances from the center in object units); it is worked out per vertex and also lowers occlusion. A card that faces the center has its normal turned outward before blending, so a blend near 0.5 no longer leaves dark cards. On a UMA character the renderer bounds cover the whole body and do not follow the head: add the **UMA > Hair Control** component (`UMAHairControl`; it was named Hair Volume Center, `UMAHairVolumeCenter`, before) to the character. Each frame, after animation, it gives the hair shader the position of the head bone (**Head Bone Name**, default `Head`) plus **Center Offset** (default 9 cm up, in the renderer's object space, turning and scaling with the head). While the component supplies the center, the material's own **Center Offset** is not used, so an offset typed in earlier to correct the bounds center cannot push the center off the head. It writes per renderer, because generated materials can be shared between characters, which takes the hair submeshes out of the SRP Batcher; without the component, or on a separate hair mesh, the shader keeps using the renderer bounds.
- Added a light sway of the hair tips to the **UMA > Hair Control** component and the URP hair shader (`UMA3_HairShader_URP`). Check **Hair Control Ready** on a hair slot (off by default) and add a Hair Control to the character: the tips then trail behind when the head moves or turns, swing back when it stops, and lean with the wind. Each slot sets **Hair Control Source** (where a vertex reads its place along the strand: the red vertex color, dark at the scalp and white at the tip; or the hair material's **ID Map**, red channel white at the scalp or green channel white at the tip), **Hair Control Start** (where along the strand the movement starts), **Hair Control Angle** (how far a strand turns about that point at full sway, in degrees) and **Hair Control Length** (the length of a strand in meters; 0, the default, measures it). A strand is turned, not slid sideways: it curves into an arc that is as long as the straight strand was, so a tip swings round and comes back a little, as a rotating strand does, and only the part of a push that goes across a strand moves it. For that the component measures each slot once from its mesh: how long a strand is, and which way it runs in the tangent frame of its vertices (so the slot needs normals and tangents). How far the hair travels follows from that length: a strand of which 3 cm move travels about 1.5 cm at 30 degrees, so short hair needs a low Start and a large Angle to show. The tips also swing when the head turns, whether the character turns on the spot or the head turns or nods: a second spring follows the head's turn rate, set by **Turn Sway** (the sway reached per radian per second; default 0.15, so half a circle a second sways the hair about half), and the shader pushes each strand by it sideways around the head, so hair on opposite sides swings opposite ways. A sudden jump to a new place or rotation is ignored. The component sets how strongly movement and wind act (**Movement Sway**, **Wind Sway**), the wind (**Wind** per character, `UMAHairControl.GlobalWind` for all, and the scene's Wind Zones with **Use Wind Zones**), **Gustiness** (the wind strength rises and falls, and its direction swings from side to side), the spring (**Spring Frequency**, **Damping**) and a **Ripple** that runs from scalp to tip. The vertices are moved in the vertex shader from one small spring per character, so no mesh is written each frame and no bones are added; the sway is simulated in Play mode only. The shader gets one set of values per material slot, so every slot built into the same submesh has to be Hair Control Ready (the component logs a warning and leaves that submesh still otherwise), and slots sharing a submesh use the first slot's values. Both passes of two-pass hair move together. See [Hair Animation: An Artist's Guide](Docs/HairAnimation.md).
- The UMA 3 hair slots (the slots in the `HairAndBeards/Hair*` folders) are now **Hair Control Ready**, with the same settings as Hair_Pointy (vertex color source, Start 0.547, Angle 44.7, measured length). The ties and scrunchies are not hair and are left as they were. HairPigtails, HairPonytail and HairAnimeMessy had no root-to-tip vertex colors (all black, or one flat grey); their colors are now made the way **Recalculate Vertex Colors from Head** makes them, from the UMA 3 head, so they sway too.
- Fixed the URP hair shader (`UMA3_HairShader_URP`) ignoring the **Normal Map** on front faces. The front-face input of the back-face flip was unconnected and fed a constant, tilted normal; front faces now use the normal map with **Normal Strength**, as back faces already did. Existing hair materials shade slightly differently on front faces as a result.
- Fixed a NullReferenceException from `DNAEffector.DNAChanged` in the UMA 3 sample scenes when a DNA slider reported a value before the panel had been given a character, for example during a UI rebuild in Edit mode.
- Added [Hair Animation: An Artist's Guide](Docs/HairAnimation.md): setting up UMA hair to sway, making root-to-tip vertex colors when a hair slot has none, and which settings suit which hair.
- The **UMA Dismemberment** inspector no longer throws `SerializedObjectNotCreatableException` after a domain reload when the object it was showing no longer exists. The UMA 2 `MaleShortHair_Slot` example slot's object name now matches its file.
