# UMA Clothes Designer implementation plan

Add **Clothes Designer** to the Vertex Editor so an artist can create and save a sewing pattern, drape it with cloth simulation on a selected UMA race in its default modelling pose, and publish a bone-weighted wardrobe item. Give the fitter a second entry point for an existing clothing slot. The drape runs on the GPU, with a CPU solver as the fallback where compute shaders are unavailable. Deliver both as an optional editor plugin. The published clothing should work in an ordinary UMA player build.

The first garment should be a two-panel sleeveless vest. Its shoulder and side seams exercise sewing, its neck and armholes must stay open, and lifting the arms exposes poor weight transfer. A loose hem makes it easy to see whether the fitter preserves the silhouette. Use that garment to prove the entire workflow before expanding the pattern library.

Status: milestone 0 implemented and validated by the maintainer on 2026-11-21. Milestones 1 to 5 implemented on 2026-11-22 and checked by script in the Editor; they await the maintainer's hands-on validation. ## Scope of the first release

| In scope | Out of scope until the vest is proven |
| --- | --- |
| One garment layer made of flat panels, sewn edge to edge, draped on one race at a time in its modelled pose. | Layered garments, self-collision, darts, pleats, gathers, multi-edge seams, sleeves and waistbands. The follow-up garments at the end of this plan decide their order. |
| A baked, bone-weighted slot, overlay and wardrobe recipe that need only UMA at runtime. | Runtime cloth. The drape is baked into ordinary skinned geometry. The tool adds no component, asset type or shader to a player build. |
| A single-layer mesh. The inside of the fabric is the back of the same triangles. | Fabric thickness, folded hems, linings and generated inside faces. See [Open decisions](#open-decisions-for-the-maintainer). |
| One mesh per bake, at a **Mesh Level** the artist chooses when creating the cloth and can change afterwards. | Generated LODs. Re-triangulating the same pattern at a lower mesh level is the intended later route, because it keeps the UV mapping. |
| Refitting an existing clothing slot without changing its topology. | Converting an existing slot into an editable pattern. |

## What the artist does

1. **Choose the race.** Start **Create Clothes on Race**, select a `RaceData` asset, and open the Vertex Editor with a temporary body built from its base recipe and default DNA. This works in an empty scene. When launched from a character, preselect its race. Offer the command through **Editors > Plugins > Clothes Designer** on the race, scene avatar, slot and wardrobe recipe inspectors and under the **UMA** menu. On a slot or wardrobe recipe it opens **Fit Existing Slot**. Show the race name and **Race Default** pose while arranging, draping and assigning bone weights. Select the body slots and mark shoulder, chest and waist landmarks. Keep those measurement locations with the fit.
2. **Draft the pattern.** Open a dockable 2D pattern canvas linked to the stage. The canvas should have rulers on the side and top, and track the mouse movement. The user should be able to enable a watermark silhouette of the race to help place and size the patterns.  Start blank or open a saved pattern. Draw closed panels with straight or Bézier edges, split an edge, enter lengths in centimetres, and mirror a piece. For the vest, draft a front and a back, make the front neckline deeper, and set the extra chest circumference desired for a loose fit. This extra circumference is garment *ease*. The small gap used to keep cloth clear of skin is a separate fit control.
3. **Sew and arrange.** Pair the shoulders and sides. Both views highlight the selected seam, its direction and the lengths of its two edges. Leave the neck, armholes and hem open. Place the front and back on the corresponding body landmarks, facing out. A reversed seam should be visible and reversible before fitting.
4. **Fit and inspect.** Pin the shoulders, start the drape, then use **Grab Cloth** to pull the front clear of the chest and release it to settle. Pause to inspect where the fabric stretches, intersects the body or gaps at a seam. Change clearance locally or return to the pattern to widen the chest. For an existing slot, enter here through **Fit Existing Slot**, capture its reference fit and refit it after changing the body. Preserve its UVs, vertex order, weights and blendshape correspondence.
5. **Publish and try on.** Save the reusable pattern and the target-specific fit independently. Choose the UMA material, overlay, race, wardrobe category and output location. Bake the garment, equip the recipe through the preview avatar's normal wardrobe flow, and inspect it in pose. A second body can use the same pattern with its own measurements, arrangement and bake.

## Creating, saving and loading patterns

| Artist action | Editor behavior |
| --- | --- |
| **New Pattern** | Open a blank draft in centimetres with a named first piece. Draw straight or curved edges, close the outline, and set the fabric grain direction (the lengthwise direction of the cloth). Name, duplicate or mirror pieces, mark openings, and pair edges for sewing. Choose the **Mesh Level** for the cloth here. The canvas can be edited before a race is selected. |
| **Save Pattern** | On first save, choose a project folder and name for a versioned Unity `ClothesPattern` ScriptableObject. Subsequent saves update that asset in place so existing fits can still find it. Allow incomplete drafts, including an open outline or an unpaired edge. Show which pieces need work before simulation or baking. |
| **Save Pattern As** | Create an independently editable pattern with a new asset GUID. Keep piece, edge and seam IDs scoped to their pattern so internal links survive the copy. Open the copy for editing. Fits and baked clothing already linked to the original keep their references. Use this command to make a vest variation from the Examples package. |
| **Open Pattern** | Select a saved pattern in the stage picker or open it from the Project window. Restore editable curves, dimensions, mirrors, seam directions, openings, grain and UV layout. Regenerate the preview from the loaded pattern. With a race selected, evaluate its dimensions on that body. Opening a saved fit additionally restores its race, arrangement, pins and accepted drape. |

Keep a working copy while editing. New, Open and leaving the stage offer **Save**, **Discard** and **Cancel** for pending changes, identifying whether they belong to the pattern or the fit. Cancelling a file picker, failing a write or opening an unreadable asset keeps the current work available. Use Unity serialization and asset references so renaming or moving a pattern in the Project window preserves links. Migrate older schemas on a working copy and diagnose unresolved piece or seam references before baking.

## Authoring data and regeneration

| Proposed record | What to persist |
| --- | --- |
| Clothes pattern (`ClothesPattern`) | Versioned panel outlines in physical units, Bézier handles, stable piece and point/edge IDs, mirror relationships, named dimensions and their defaults, directed seam spans, intentional openings, grain direction and UV packing settings. Store island placement keyed by piece ID. Keep the editable flat pattern independent of the avatar and triangulation. |
| Clothes fit (`ClothesFit`) | Pattern reference or existing slot reference, race and reference-body revision, ordered body slots, reference DNA and pose, landmarks, panel placement, ease overrides, fabric settings, collision clearance and pins. Store persistent controls in panel coordinates or on the original slot topology. Save an accepted drape as positions with a topology and source revision, so reopening a hand-shaped fit restores the folds. |
| Generated output | Standard UMA slot and wardrobe assets. Keep source and output references and their bake revision in the authoring data. A player loading the recipe needs only UMA and the baked assets. |

Authoring assets may reference baked output. Baked output never references a pattern or a fit, so a player build cannot pull in an editor-only type and removing the plugin leaves the clothing intact. Save patterns, fits and recovery data under `Assets/UMAProjectData/ClothesDesigner` by default, outside the plugin folder, so they survive removal and reinstall. They need the plugin's types to open again. Make piece, edge and seam IDs serialized values generated when the element is created. Never derive an ID from `GetInstanceID()`, a list index or a vertex index.

**Units and measurements.** Draft in centimetres and simulate in race-root space, where one Unity unit is one metre, so gravity, clearance and bend stiffness mean the same on every race. Check that assumption per race by comparing the captured reference body's height with `RaceData.raceHeight`, and report a race whose generated root carries a scale instead of silently drafting at the wrong size. Define each body measurement so two people get the same number: a circumference is the perimeter of the convex outline of the selected body slots cut by a plane through the landmark, perpendicular to the spine direction stored with the landmark. Store a landmark as a body slot, triangle and barycentric position, like a body pin, so it follows DNA changes and is flagged after a topology change. Show the measured value beside the landmark.

Give a pattern dimension either a fixed length or a measurement with an allowance. For example, a 96 cm chest with 8 cm of ease gives the vest a finished chest circumference of 104 cm. For equal front and back panels drawn as mirrored halves, each half is 26 cm wide at the chest line. On a 108 cm chest the same pattern evaluates to 29 cm per half. The neckline depth can keep its own fixed measurement. Show the evaluated dimensions before fitting so the artist can distinguish a sizing error from a drape problem.

**Mesh Level.** The artist sets how finely the cloth is meshed when creating it, and can change it at any time before baking. Offer named levels and a custom value, each defined as a target edge length in centimetres, so the same level gives the same fabric detail on a small piece and a large one. Show the vertex and triangle counts the level produces for the current pattern beside the control, before anything is simulated. Store the level with the pattern as its default and allow the fit to override it, so one pattern can be baked coarse for one target and fine for another. A lower level while fitting and a higher one before the bake is a normal way to work: the accepted drape is resampled through panel coordinates, then settled again.

Changing a curve or the mesh level regenerates the mesh from the pattern. Resample pins and local edits from their panel coordinates and identify edits whose panel was removed. Invalidate body bindings when either topology changes. Treat downstream edits made directly to a baked slot as an independently edited result. Offer a new output or an explicit update of the linked assets, preserving their GUIDs and reporting which edits the update would replace.

## UVs from the sewing pattern

Generate the slot's primary texture coordinates (UV0) from the **flat sewing pieces as drawn** (before the sizes are applied, so graded sizes share one layout). A print placed on the left front of the flat vest should land on that same piece after sewing, grabbing and draping. A fold can hide part of the print while the fabric carries it through the fold.

1. Validate closed, non-self-intersecting outlines, then use constrained triangulation to retain seam samples, openings and panel winding. Keep the originating piece ID and flat 2D coordinates for every triangle corner, including curve samples and interior vertices. Derive UV0 before the 3D arrangement. Give each cut piece its own island. At a sewn edge, keep both panels' UVs on separate render vertices while sharing the physical seam position and bone weights.
2. Pack islands in the slot's local 0–1 texture space. Use one physical-to-texel scale and account for texture aspect ratio so each island retains its outline, proportions and relative size. Align the grain consistently, give mirrored pieces distinct space with readable print orientation, and include a pixel gutter at the chosen bake resolution. If the pieces exceed the available area, reduce density uniformly and report the resulting density. UMA can subsequently remap these slot-local coordinates into its material atlas. [UMA mesh combiner](../Core/StandardAssets/UMA/Scripts/UMADefaultMeshCombiner.cs)
3. Save each island's packing transform with the pattern. Moving pieces on the drafting canvas, simulating, posing or reopening leaves the UV layout intact. A finer triangulation samples the same 2D mapping. If a pattern or size change makes islands overlap or exceed their reserved space, identify the pieces and preview an explicit **Repack UVs** before moving painted regions.
4. Show the outlines and grain arrows over a labelled checker texture in 2D and 3D. Flag missing source coordinates, collapsed UV triangles, flipped prints or island overlaps on the affected piece. Derive UVs for any new geometry from its owning piece or edge where possible. Where a reliable mapping is unavailable, require a resolved mapping before bake. **Fit Existing Slot** retains its authored UV channels. [Scene Mesh Slot Builder](../Core/Editor/Scripts/SceneMeshSlotBuilderWindow.cs)

## Sewing, pinning and Grab Cloth

**Sewing.** Select a start and end on each panel edge or edge span. Draw correspondence lines between paired endpoints in both views and provide **Reverse**, **Unsew** and Undo. Store each span by edge ID, interval and direction. Sample both spans at matching fractions of arc length so a curved edge and its partner have corresponding stitch points even at different mesh densities. Display length mismatch, crossed direction and any span already paired elsewhere. Keep intentional openings free. During simulation start paired particles apart and progressively shorten stitch constraints. Once settled within tolerance, bake each pair to one physical seam position with coincident render copies. An unresolved seam stays highlighted for repair. Deliberate gathers and multi-edge seams are later extensions.

**Pinning.** Pick a point or paint a weighted region in either view. Show the same pin on the panel and on the draped garment. A placement pin holds cloth at a point in race-root space. A body pin follows a selected body triangle using barycentric coordinates and an offset. Full weight holds the target, partial weight permits movement, and erasing a pin releases the cloth. Persist panel coordinates, body-slot identity, target and strength in the fit. Rebuild pins after remeshing and flag pins requiring a new body target after a topology change. Pins constrain the drape. Bone weighting remains a separate bake step.

**Grab Cloth.** In the stage, press on the visible garment to pick the frontmost cloth triangle, then drag a radius of connected fabric toward the cursor on the initial hit-depth plane. Use a soft falloff and strength control. Follow sewn adjacency while respecting open boundaries and pins, so grabbing the vest front cannot accidentally pull the back through the body. Send temporary grab targets into the running solver. Keep stretch, bend and collisions active during the stroke. Release removes the grab and lets the cloth settle. **Pause** and **Keep Drape** capture a shape the artist wants to preserve. Escape restores the pre-stroke state, and one completed drag is one Undo/Redo operation. The existing cloth-brush proposal describes compatible stage gestures. This garment brush operates on the active simulated cloth. [Mesh Modifier cloth brush plan](MeshModifierClothBrushPlan.md)

## Cloth simulation in the editor

Use an XPBD (extended position-based dynamics) solver, the same model the cloth-brush plan proposes, so stiffness stays comparable when the substep count or mesh density changes. Take every rest length, rest area and rest bend angle from the flat pattern, never from the arranged 3D panels. That is what makes the drafted ease appear in the drape. Weld each sewn pair and each split vertex into one particle once the seam has closed.

The cloth-brush plan defers both GPU simulation and sewing, because its brush solves a small local patch for a single stroke. A garment drape solves the whole garment, with seams, for many seconds, which is why this plan builds the GPU solver first. That brush is not implemented yet, so nothing here depends on it. If both are built, share the constraint definitions and the body collision index and keep the two front ends separate. [Mesh Modifier cloth brush plan](MeshModifierClothBrushPlan.md)

**Two solvers, one constraint set.** The GPU solver is the primary path and is built first. A CPU solver for the same constraints is required as well, for two jobs. It is the fallback that runs **Simulate** where compute shaders are unavailable, and it is the oracle for the automated tests, which must pass in batch mode on a machine without a compute-capable GPU. It is also how a wrong GPU result is told apart from a wrong constraint. Build both from one description of the particles and constraints so they cannot drift apart. Write the CPU solver with Jobs and Burst, which Core's editor assembly already uses, and start it as plain correct code in milestone 1. Making it fast enough to fit with is milestone 3.

Use Unity compute shaders for the GPU solver. The CPU evaluates the pattern, triangulates it, builds constraints and prepares a spatial index for the selected collision surfaces. Before the first step, check that no particle of the arrangement starts inside the body, and offer to push an offending panel out along its landmark normal. A drape that starts inside the body cannot recover. Upload particles, rest lengths, triangles, stitches, pins and body geometry once per relevant change. Run fixed substeps on the GPU for gravity and damping, stretch and bend, gradual seam closure, pin and grab targets, and collision with the body at the requested clearance. Partition constraints that write to the same particle into separate batches or accumulate corrections into separate buffers. Refresh the body collision surface after a race rebuild. Keep collision surfaces and bone-weight donors independently selectable. [Unity compute shaders](https://docs.unity3d.com/6000.3/Documentation/Manual/class-ComputeShader.html)

Expose **Simulate**, **Pause**, **Step**, **Reset to Arrangement** and **Keep Drape**. Provide draft and final solver quality, which set substeps and iterations, and fabric controls for stretch, bend and damping. Solver quality is separate from the Mesh Level, which sets how many particles there are. Bound editor substeps to keep the stage responsive. Start with a single garment layer, flag self-intersections for correction, and measure layered self-collision separately. Choose the solver once, when the stage opens: the GPU solver where `SystemInfo.supportsComputeShaders` is true, otherwise the CPU solver. Show which one is running beside **Simulate**, and offer **Use CPU Solver** as a manual switch so a driver problem does not block the artist and so both paths can be compared on one machine. Every control, pin, grab and capture behaves the same on either solver. The CPU solver is slower, so show the particle count at which it stops being interactive and suggest a lower Mesh Level while fitting. [Unity compute shader capability](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/SystemInfo-supportsComputeShaders.html)

On the GPU solver, render the live preview from GPU positions. Capture a consistent completed step for Undo, **Keep Drape** and bake. Use asynchronous GPU readback where supported and a bounded synchronous capture at those explicit boundaries otherwise. The CPU solver uploads its positions to the preview mesh after each displayed step and captures directly. Associate captures with the fit and topology revision, discard stale completions after edits or stage exit, and release buffers once outstanding operations finish. Recover the last valid state after a cancelled or non-finite solve. A saved fit reopens paused on its accepted drape when its source revision matches. A stale drape is marked for regeneration. Baking writes ordinary skinned geometry and uses the same battle-buddy normal rules as the rest of UMA. [Unity GPU readback](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Rendering.AsyncGPUReadback.html)

Keep the compute shaders in the plugin folder and outside any `Resources` folder, and load them through the plugin's own asset path, so they are never included in a player build. Pause the solver and release its buffers before an assembly reload, on entering Play mode and when the stage closes. Keep the working copy of the pattern and fit serialized across the reload, and write a recovery copy under `Library/UMA/ClothesDesigner` so a crash during a long session does not lose the draft.

## How the fit becomes a wearable

**Race reference for bone weighting.** Build the temporary avatar from the selected race's own base recipe, default DNA and base body slots. Use the Vertex Editor's modelled-pose setup after generation and after any rebuild, including suppression of stored humanoid posing on the temporary avatar. Use that race's actual modelling pose, including races authored with angled arms. Pause animation and IK while capturing the body surface, skeleton, root transform, bind poses and bone weights together. Use this same snapshot for placement, body collision and weight transfer. Adapt the slot builder's target-capture path so its internal avatar regeneration cannot change the pose between draping and sampling. Changing to an animation or DNA variant opens a try-on preview. Returning to **Race Default** restores the weighting reference. If required body geometry, bones or bind poses are missing, identify the race and missing inputs before allowing a weighted bake. [Vertex Editor modelled pose](../Core/Editor/StageUtils/VertexEditorStage.ModelledPose.cs) · [Scene Mesh Slot Builder](../Core/Editor/Scripts/SceneMeshSlotBuilderWindow.cs)

**Skinning and DNA.** Reuse the Scene Mesh Slot Builder's closest-triangle weight interpolation, bone remapping and conversion into slot bind space. Share the relevant routines behind its existing window. Allow garment panel or region restrictions and show unmapped or ambiguous vertices before bake. For a reusable slot, establish the base bake on the race's reference shape. Check it on the requested DNA variants using the equipped recipe. Bone-driven changes follow skinning. Body blendshapes that move the skin independently may need a corresponding clothing shape, which can be authored through the conformer and tested at matching weights. A successful fit on one preview does not establish a supported DNA range. [Scene Mesh Slot Builder](../Core/Editor/Scripts/SceneMeshSlotBuilderWindow.cs) · [Clothing Conformer](../Docs/ClothingConformer.md)

**Refit an existing slot.** Bind the garment to its source body before changing the body. Reuse the conformer's triangle mappings, signed offsets, welded-seam handling, topology checks and save-as-slot or blendshape operations. For loose regions, let the artist restrict donor regions, pin attachment points or relax around them. Highlight vertices beyond binding distance for correction. A different body topology requires fresh landmarks and a new fit. For a loose region, run the cloth solver on the slot's own topology: one particle per battle-buddy group, rest lengths from the captured reference fit, no pattern and no sewing. Write the result back to every copy in the original vertex order. Existing blendshapes keep their deltas, so check each one on the refitted base before saving. On every preview or bake that recalculates normals, use `UMABuddyNormals` so coincident UV and slot-edge battle buddies share one normal. The Scene Mesh Slot Builder's missing-normals fallback already does this through `CalculateMissingNormals`. Keep that routine when its code is extracted. [Clothing binding data](../Core/Scripts/ClothingConformer/ClothingBindData.cs) · [UMA buddy normals](../Core/StandardAssets/UMA/Scripts/UMABuddyNormals.cs)

**What the bake writes.** One `SlotDataAsset` whose mesh holds positions in slot bind space, UV0 from the pattern, normals from `UMABuddyNormals`, tangents computed from those normals and UV0, bone weights, bind poses and bounds. It has one submesh and no blendshapes. Seam and UV-split copies are coincident and carry identical weights. Report the vertex and triangle counts before writing, and name the Mesh Level that produced them. Write an overlay and a `UMAWardrobeRecipe` with the chosen race compatibility and wardrobe slot. A single-layer garment shows its inside at the neck, armholes and hem, so warn at publish when the chosen `UMAMaterial` culls back faces. After publishing, the slot opens in the existing Slot Weight Editor for touch-up like any other slot.

**Hiding the body under the garment.** A body left whole under clothing pokes through as soon as the avatar moves, and the Scene Mesh Slot Builder writes no mesh hide. Offer **Generate Mesh Hide** at publish, using the existing occlusion generator with its Strict strategy so that only triangles covered at all three vertices are hidden. Add the result to the recipe's mesh hides. Leave it off by default for a loose garment and preview the hidden triangles first: the vest's open neck, armholes and hem show skin that a careless hide would remove. [Mesh hide generator](../Core/Editor/Scripts/UMAMeshHideAutoGenerator.cs) · [Mesh hide assets](../Docs/MeshHideAssets.md)

**Stage and publishing.** The stage and its linked Mesh Modifier window currently select among four built-in workflows. Add a small editor-side extension point for Clothes Designer activation, scene input, preview rebuilds, unsaved work and cleanup. The plugin owns the canvas and temporary garment mesh. Keep drafts out of the stage's baked body mesh and its index-based sculpt adjustments. Integrate Save, Discard and Cancel with the existing leave-stage dialog. For publishing, share the Scene Mesh Slot Builder's slot validation, overlay, recipe and library registration logic. Validate in memory first and roll back partial asset or index changes if publishing fails. [Vertex Editor stage](../Core/Editor/StageUtils/VertexEditorStage.cs) · [Mesh Modifier editor](../Core/Editor/Scripts/MeshModifierEditor.cs) · [Stage saving](../Core/Editor/StageUtils/VertexEditorStage.Saving.cs)

## Core changes the plugin depends on

The plugin can only reference public editor API, and Core must gain no reference to a Clothes Designer type. This work came first, as milestone 0, and is done. The table records what each change became.

| Core change | Where it stood | What Core now offers |
| --- | --- | --- |
| Stage workflow extension point | `MeshModifierEditor.AuthoringWorkflow` is an internal four-value enum the stage and the window switch on. | `VertexEditorWorkflow` and `VertexEditorWorkflows.Register`. A plugin workflow gets a button on a second row of the workflow bar, the Scene view panel, the window body, the Scene view's events, a callback after each character rebuild, a part in the leave dialog and a closing callback. A plugin workflow is never remembered: opening the Vertex Editor always gives the built-in workflow used last, and the plugin starts its own workflow from its own command. |
| Race-only stage entry | `ShowStageForSlots` required a list of slots to edit. | `VertexEditorStage.ShowStageForRace(race, out message)`. `ApplyModelledPose`, `CreateTPoseWithoutHumanPose`, `Character`, `CharacterRace`, `CharacterRenderer` and `OwnsTemporaryCharacter` are public. |
| Reference capture and weight transfer | Private members of `SceneMeshSlotBuilderWindow`. Capture always regenerated the avatar. | `UMASlotSkinTransfer`: `CaptureTargetData(avatar, rendererIndex, regenerate)`, `BuildTargetSurface`, `TransferWeights`, `TryFindClosestTriangle`, `BuildSlotMesh` with `SlotMeshOptions`. Geometry without a source mesh is accepted, which is what a pattern-made garment is. The code was moved unchanged and the window calls it. |
| Slot, overlay and recipe publishing | Private instance methods reading window fields. | `UMASlotPublisher`: `Validate(request)` writes nothing, `Publish` builds and checks the slot in memory before touching the project, registers with the Global Library last and removes what it created when a step fails. `Rollback(result)` takes a finished publish back. |
| Slot mesh normals | `BuildSlotMesh` fell back to `Mesh.RecalculateNormals()`. | `UMASlotSkinTransfer.CalculateMissingNormals`, which uses `UMABuddyNormals`. |

Two things the later milestones must respect, found while doing this. A slot fails validation unless it has tangents or is published with tangents cleared, so the bake has to write them. A wardrobe recipe only loads its slot back once the slot is in the Global Library, so a try-on right after publishing needs the library registration to have happened.

Changes from the plan, made while implementing:

- **UV islands come from the pieces as drawn, not as sized.** With sized pieces, fitting on a heavier body pushed the pieces out of the texture. Now graded sizes share one layout; only redrawing the pattern can need Repack UVs.
- **The live preview is updated by asynchronous readback** of the GPU positions, not rendered straight from the GPU buffer. It is a frame behind and keeps one preview path for both solvers.
- **Collision tests 8 candidate triangles per particle, gathered once a frame** (both solvers), which made the CPU solver about twice as fast.
- **Friction is Coulomb** (grip limited by how hard the cloth is pressed in), and **seams are solved after every other constraint** in each pass. Together they closed the shoulder seams from about 10 mm to 0.00 mm.
- **After a body shape change the pieces are laid out round the new body again** instead of keeping the old drape, which started partly inside a larger body.
- **Mesh hides keep body triangles within 4 cm of an opening visible**, so no holes show through the neck, armholes or hem.
- **Fabric per piece, with presets** (asked for by the maintainer, 2026-11-22): the fabric moved from the fit to each pattern piece (cotton body, elastic band). Stretch and bend compliance are per constraint, weight and friction per particle, in both solvers. Presets were tuned by measured drapes: the solver holds any stretch compliance below about 0.03 and bend compliance below about 0.3 as firm as it can, so firm fabrics differ mainly in weight and grip. A fabric change carries on from the current drape. Fits keep only damping and clearance (fit format 2; pattern format 2).
- **Inside facing and rim** (asked for by the maintainer, 2026-11-22): turned-in copies of the cloth near the openings (depth measured along the cloth from every opening vertex, carried across seams, default 5 cm), facing inwards, with the cloth's UVs and weights, 0.5 mm inside it; an optional rim joins each opening edge to its copy, the facing then lying the rim's thickness inside. Vest at Medium: 617 facing and 268 rim triangles; every copy carries its source's weights. The maintainer's check found the rim stopping one segment short at one end of every opening: an edge's last corner is stored as the next edge's first point, so judging segments by their points dropped the segment into that corner. Segments are now assigned to an edge by the pair of points (two edges in a row: the first), which also counts the corners as part of the opening for the facing depth (a few more rim triangles than the count above).
- **Fine drape, coarse slot, normal map** (asked for by the maintainer, 2026-11-22): the slot can be baked at its own Mesh Level; its mesh takes its shape from the drape through the flat pattern (`PatternMeshSampler`), and the drape's finer folds are baked into a tangent-space normal map by rasterising both meshes in their shared UV layout (no rays). The slot's frame is computed in the drape's space (the slot's bind space is the same space turned 90 degrees about X; tangent-space values do not change under one turn: checked to 0.02 degrees). Measured on the vest at 5 mm baked at 2 cm: 22,842 to 1,480 vertices, slot triangle centres 0.96 mm from the drape on average, map 9.2 degrees mean detail; bake 3 s. Substeps now grow with mesh fineness (12 at 2 cm, 48 at 5 mm): mean stretch at 5 mm went from 4.3% to 0.76%. Rebuilding a 5 mm cloth went from 8.3 s to about 1.7 s (edge keys hashed by halves collided; the constraint colouring used sets per colour).
- **Darts and pleats** (asked for by the maintainer, 2026-11-22): darts and pleats are their own objects on a piece (edge, position, width, point, curve; pleat type, depth, stitched length, pressing), not points in its outline, so they stay editable and a seam on their edge stays one seam. The mesher cuts an edge dart's legs into the outline, leaves a hole for a diamond dart, and runs pleat folds into the piece as mesh lines; all are sewn shut. Seams skip what darts and pleats take out of an edge, sizes count only the fabric left, and pleats are laid out folded with pressed creases (bend rest folded, compliance 0.5: folded at the waist, open over the hips, measured on two skirts). Curved dart legs are pulled towards the dart's centre line by a share that grows to the point, so they can never cross.
- **Place tool** (asked for by the maintainer, 2026-11-22): drag a piece round the body, up and down, and (Shift) out from it in the Scene view; placements gained a Distance and are edited on the pattern, so the Pattern Canvas, the panel and the window show the same values.
- **Pieces round arms, legs and the head; twenty sample patterns; converting modelled clothes** (asked for by the maintainer, 2026-11-22). Placement gained a body part (torso, head, either arm, either leg), Lay Flat and Across. Arm pieces wrap a cylinder along the shoulder-to-wrist axis (0 the top of the arm, 90 its front); leg pieces an upright cylinder round the hip-to-ankle line that turns into the torso's oval between the crotch and 12 cm above it, so trouser halves meet at the centre front and back; the head an oval like the torso's. The body's joints, crotch, limb radii and new measurements (arm length, waist to ankle, inseam, neck, head, thigh, upper arm) come from the skeleton and surface: on Human Female 3.0 arm 56.9, inseam 88.2, neck 41.0, head 63.6 cm. Twenty samples are built in code (`SamplePatterns`, with `PatternBuilder`), drafted for the default female and sized by chest, upper arm, waist, hips, inseam or head; all 20 drape and stay on Human Female 3.0 with seams closed but for one sock sole and some ankle cuffs (2-5 cm open), and on Human Male 3.0 with looser tops (sleeve and side seams up to 2 cm open) and skirts sitting at the hips. Trousers sit at 1.20 m, where both default bodies measure about 90 cm round. Measured on the way: stretchy presets were 5-10 times too soft (spandex leggings stretched 50% under their own weight and slid off): jersey 0.1 to 0.05, elastic 0.3 to 0.08, spandex 0.4 to 0.1; stretchy trousers are cut smaller than the body. Limp silk hanging from the waist still slides off at 12 substeps (it holds at 24, but 24 made the stiff bending unstable at 2 cm, so the substeps stay; the circle skirt is wool). The converter (`PatternFromMesh`) makes each UV island a piece at its 3D size, measures baked-in folds by Taubin smoothing and shrinks the piece by them, sews islands where their boundaries share welded points, places each piece round its part, and keeps the original UVs. A sample drape converts back to the same 4 pieces within 2% of their size, sews up again with nothing in the body; the UMA 3 skirt and hoodie convert to 6 and 14 pieces that need tidying on the canvas (unpaired stretches, slivers).
- **Collars: mesh detail, interfacing and folded seams** (asked for by the maintainer, 2026-11-22). A piece can be meshed finer than the Mesh Level (Mesh Detail 1-4; seams pair by the finer side; the bend floor follows each piece's own edge). Interfacing (Light, Firm) adds distance constraints from each point to the points two edges away that lie mostly up or down the piece as drawn, so it resists folding across its height but curves round the neck. A Folded seam joins a piece turned over another (not reversed); crease constraints across it hold the turn as laid out. The sample oxford's collar is a firm arc-cut stand (ends rising 2.5 cm, top edge shorter than the neck edge) and a light leaf on a folded seam, both at detail 3; cuffs firm at detail 2. Measured on Human Female 3.0: the leaf turns down over the stand and lies open on the chest like an unbuttoned collar; interfacing lowers the stand's crumpling (mean fold between triangles 16 to 12 degrees) and keeps the leaf turned under (66% to 80%). Firm at 0.0005 and 0.00005 drape the same: at the collar's detail both are as stiff as the solver holds. Tried and dropped: holding ordinary seams next to interfaced pieces straight on (it made the collar crumple more, 19 against 12 degrees, because a neckline seam is not straight on the body) and a rectangular band (it lies down at the front however stiff). Buttons (two fronts held together) are not possible yet.
- **Cloth Tools toolbar** (asked for by the maintainer, 2026-11-22): Place, Grab, Pin and Erase Pin are also a Scene view toolbar overlay (move, hand, eraser icons from the editor; the pin drawn in code, as the editor has none), each with a tooltip shared with the panel's buttons. - **Show Seams** (added after the maintainer's first hands-on check, 2026-11-22): the Scene view draws each seam's two edges in its Pattern Canvas colour and a thread between every pair of points being sewn, faint where hidden; a toggle in the Fit section turns it off.
- **Fine meshes settle, and run faster** (reported by the maintainer, 2026-11-22: a Very Fine drape never stopped and was slow). Cause: near-rigid bending (compliance 2e-5) is unstable on fine meshes, on the CPU solver as much as the GPU, so the cloth trembled forever; more substeps made it worse. Bend compliance now has a floor of 0.003 / edge² (edge in cm: none to speak of at 2 cm, 0.003 at 1 cm, 0.012 at 5 mm), found by sweeping it. A 1 cm vest settles to 0.002 mm a frame (was 0.21) and a 5 mm vest to 0.0125, both under the 0.05 mm settle test, which now counts simulated frames rather than wall time. Edges over 20% stretch at 1 cm went from 15 to 4. The GPU runs a whole frame as one dispatch of one workgroup for cloth up to 2,500 points (1.62 against 1.82 ms a frame at 2 cm); larger cloth keeps a dispatch per stage, which is faster there (1 cm: 2.42 against 3.23 ms; 5 mm: 3.57 against 15.86 ms); both give identical positions. The designer queues 3 GPU frames a tick. The fit report (once a second while simulating) searches the body near each point first, in parallel: 113 / 449 / 1,772 ms to 8 / 27 / 92 ms at 2 cm / 1 cm / 5 mm, with the same nearest point for every point; ties at a shared body edge now take the triangle whose normal best matches the offset, so inside or outside no longer depends on search order.
- **Baking again updates the existing assets in place** (`UMASlotPublisher.Request.UpdateInPlace`), keeping painted overlay textures and anything added to the recipe.

Known limitations:

- **Edge stretch at final quality exceeds 5% on a few edges.** The average is 0.4-0.6%. At the armhole corners, where the shoulder seam carries the panel's weight, 24 of 4,208 edges (female, max 14%) and 64 of 4,842 (male, max 30%) exceed 5%. On the female vest at 1 cm, the four edges next to the shoulder seam's ends (front and back, neck and armhole side) stretch 39-48% (rest 9.8 mm, about 4.5 mm longer), 158 of 16,844 edges exceed 5%, mean 0.55%; this was there before the bend floor (62% without it). - **Cloth on cloth** is handled since 2026-11-23 (see below): between pieces, within a piece where it folds over, and in layer order. Clothes made as separate slots still do not collide with each other in a game; layering is a fitting aid.
- **The Wardrobe Recipe is added to the Global Library with `UMAAssetIndexer.ForceSave`,** as the Scene Mesh Slot Builder always did; that writes the library's whole in-memory state. Slots and overlays go in one item at a time.

## Sleeve layout and the Close button (2026-11-23)

Reported by the maintainer with a long-sleeve tee on Human Female 3.0. The sleeves sewed shut above the forearms, and the maintainer could not tilt them down or bring the cuffs in. The Vertex Editor's Close button also did nothing.

End Distance +2 cm made the far ring 2 cm wider, and Faces +10° gave angle 10 (-10 on the left arm). A test checks that the rings lie where the pieces are laid: at least 90% of points within 6 mm (a sleeve cap's width changes within a row). 141 Clothes Designer tests pass. The handles themselves were not dragged with a mouse.
- Legs keep one radius (`legRadius`). A trouser leg narrower at the ankle than that tube could close the same way; not seen in the samples.

## Open decisions for the maintainer

Each has a default the plan proceeds on if nothing else is decided.

| Decision | Default | Why it matters |
| --- | --- | --- |
| Inside of the fabric | Single layer, with a publish warning when the material culls back faces. | Generated inside faces double the triangle count and need their own normals and UV treatment. A folded hem needs pattern support. |
| Mesh hide at publish | Offered, off by default. | On by default suits tight clothing and risks holes under loose clothing. |
| Fixture race for the manual acceptance run | The UMA 3 human race the Examples package targets. | Fixes the measurements recorded with the results. Examples already depends on UMA 3 content. |
| Where the stage extension point is versioned | The plugin manifest's minimum core version. The launcher API stays at version 1. | Bumping the launcher API version would affect every existing plugin's manifest. |

## Risks

- **The core extraction is the largest hidden cost.** The stage is about 16,000 lines and the slot builder about 2,600, almost all private. Milestone 0 exists so that this work is sized and reviewed on its own instead of surfacing inside milestone 1.
- **Closest-triangle weights fail where fabric hangs away from the body.** A hem between the legs or under a raised arm can take weights from the wrong limb. The vest keeps this mild. The donor-region restriction, the ambiguous-vertex display and the Slot Weight Editor are the mitigations, and the skirt fixture is the real test.
- **A GPU drape is hard to test and not bit-identical across graphics APIs.** The CPU solver and the stated tolerance against it are what keep the automated tests meaningful. Record GPU and graphics API with every measurement.
- **Two solvers can drift apart.** A fix made in one and not the other makes a drape depend on the machine it was fitted on. Building both from one constraint description, and the GPU-against-CPU comparison in the tests, are the guard.
- **The CPU solver may be too slow at a high Mesh Level.** Body collision dominates the cost. Showing the particle count, suggesting a lower level while fitting, and resampling the drape when the level is raised keep the fallback usable without promising GPU speed.
- **Constraint order on the GPU changes the result.** Batch colouring must be deterministic for a given topology, or **Keep Drape** and Undo will not reproduce a shape.
- **A high Mesh Level can exceed a sensible game budget.** The counts shown beside the Mesh Level control and again before baking let the artist see the cost while fitting, not after publishing.
- **Body measurements can disagree with the artist's expectation.** A convex perimeter ignores the hollow between the shoulder blades or the breasts. Showing the measured value beside the landmark and the evaluated dimensions before fitting lets the artist correct with ease instead of guessing.

## Reference workflows

- Drawing flat pieces, pairing directed seams and arranging them around an avatar are established garment-authoring operations. Use these operations with UMA stage selection and an original pattern canvas. [Simply Cloth](https://superhivemarket.com/products/simply-cloth) · [Divine Cut](https://superhivemarket.com/products/divine-cut-smart-cloth-generator)
