# UMA Overlay Painter

Overlay Painter is a Unity 6.3+ preview stage for painting generated `DynamicCharacterAvatar` materials without the color multipliers used while UMA composes overlays. It reconstructs every generated renderer into one static preview mesh per material, preserving the baked geometry, source UVs, source material, and generated texture set.

For the complete artist guide, see [Overlay Painter](Documentation/OverlayPainter.md).

See [Clothing Finishes and Material Import](Documentation/ClothingFinishesAndMaterialImport.md) for wetness, sweat, leather, coated fabric, print aging, automatic seam paths, and PBR texture-set import.

Use **+Path → Generators** for [path generators](Documentation/PathGenerators.md): Scar and Wound, curved and tribal Tattoos, Text and Lettering, stitching, seams, piping, zippers, and linear tears. Tattoo has independent endpoint taper/curl controls and transparent cutouts; tribal designs also have procedural arm counts, placement, length, angles, symmetry and seeded variation. Lettering has a selectable Font. Both share their visible silhouette across every material channel. Generator settings are editable in the dockable Properties window.

Overlay Painter ships as an optional UnityPackage for UMA launcher API 1. Install or update it with **UMA > Plugins > Install Overlay Painter**. Examples and tests are separate packages. Project settings, authored documents, recovery, and exports remain in `Assets/UMAProjectData/OverlayPainter` when the plugin is removed.

## Open the stage

### From a slot (recommended for authoring)

1. Select one `SlotDataAsset`. Find **Editors > Plugins** above the inspector controls in either view.
2. Click **Overlay Painter**.
3. Choose either an `UMAMaterial` or an `OverlayDataAsset`, review the material capability summary and working resolution, then click **Open**.
4. For a UDIM slot, review the tile/member source table. The complete exact-ID group opens, frames, selects, and paints as one logical target; individual tiles are diagnostic members, not independent paint targets.

This path reconstructs the slot directly from `UMAMeshData` and never searches for or generates an avatar. An `UMAMaterial` source starts with a removable **Default White** flat Fill layer and semantic-neutral bases. An `OverlayDataAsset` source uses that overlay's material and textures as immutable bases. For UDIM groups, assign compatible overlays explicitly per member; unassigned members receive semantic-neutral bases rather than guessed companion overlays.

### From an avatar

1. Put a `DynamicCharacterAvatar` in an open scene and generate it.
2. Select the avatar and find **Editors > Plugins** above its inspector controls.
3. Click **Overlay Painter**.
4. Select one or more slots, select OverlayData when using the Overlay source, then choose a target channel, tool, and brush. Paint directly in the 3D Scene view.

**Compact View** under **Project Settings > UMA > Overlay Painter** defaults on. It opens one floating workspace with **Overlay Painter Layers**, **Overlay Painter Brush**, and **Overlay Painter Properties** as the left tab group and a dedicated **Scene** view plus **Overlay Painter 2D** as the right tab group. The 40/60 split is resizable, Layers and Scene are initially active, the selected Body target is framed, and window geometry is remembered. Overlay Painter's 3D, Path, and painting toolbar overlays register hidden, become visible only while an Overlay Painter stage is active, and are bound exclusively to that dedicated Scene tab in Compact View. Unity layout restoration is reconciled automatically so they remain hidden in fresh projects and other Scene windows. Use **Layout > Reset Compact View** or **Window > UMA > Reset Overlay Painter Compact View** to restore the arrangement. Disable the setting to open Layers, Brush, Properties, and 2D as traditional dockable windows and use the existing Scene view. **Overlay Painter Layers** contains the global toolbar and a space-saving tab group that switches between the searchable Paint Target navigator and the full-height Layer/Path stack. **Overlay Painter Properties** hosts the contextual inspector in its own dockable tab. **Overlay Painter Brush** owns the brush Asset Shelf together with Brush and Stroke/Projection controls; its toolbar can hide or restore the shelf, and the horizontal divider resizes it. All 13 painting-palette controls live in the native Scene-view **Overlay Painter Toolbar** overlay: Paint, Erase, Blur, Smear, Clone, Dodge, Burn, Normal Touch-up, Plugin Brush, Polygon Fill, UV Island Fill, Path, and help. The former dockable toolbar is no longer opened or offered in the Window/Layout menus; serialized legacy instances close themselves after layouts reload. Every character launch gives startup priority to a logical target whose visible name contains the standalone word **Body** and enables **Isolate** by default for fresh or legacy workspace state; its saved target is the fallback only when no such Body target exists, while an explicit current Isolate choice is retained. Standalone slot launches are unchanged. Workspace selections persist in the avatar recipe state. The 3D Scene-view controls include a full-width **Shutdown Overlay Painter** button that uses the normal Save/Discard/Cancel close flow. Compilation, assembly reload, and Play Mode transitions close the custom stage and immediately hide all Overlay Painter Scene-view toolbars so no inactive toolbar remains behind.

Recoverable import conditions do not interrupt stage opening. A yellow warning icon appears beside each affected logical target, expanded UDIM member, and Texture Set; click it to open the complete code, severity, material, slot scope, and message. Conditions that cannot be associated with reconstructed geometry use the warning icon beside the target search controls. The Scene view also shows a passive notice along its bottom for about ten seconds and fades it during the final 2.5 seconds. Reconstruction failures that make painting unsafe still stop the launch and report the error.

The paint source uses a three-way **Texture / Overlay / Color** selector. The Texture tab accepts either a complete Texture2D or an individual Sprite from a sprite sheet. A Sprite is extracted into a cached temporary texture while its Sprite asset remains the persisted layer source; neither the Sprite nor its sheet is modified. Extraction is channel-aware: changing the active channel selects or creates the matching cached texture. Normal-channel Sprite regions, raw RGB normal textures, and textures imported with Unity's Normal Map importer are converted to linear, normalized tangent-space RGB before painting. The selected OpenGL/DirectX convention describes the source; DirectX green is flipped into Overlay Painter's canonical OpenGL working representation before vector blending. Cache entries are separated by channel and convention, so the same Sprite can safely be used as both color and normal data. Texture samples the selected image inside each brush stamp, Color uses the selected solid color, and Overlay provides an **OverlayData** popup aggregated from the selected slots. Overlay textures are routed together to Albedo, Normal, Metallic, Roughness, AO, or Emission according to the overlay material's UMA channel keywords. The separate Paint Target control chooses whether those results affect the editable base copy or a non-destructive layer. Source assets are never changed in place.

The layer toolbar uses split **+ Paint** and **+ Fill** buttons. Their main areas retain the quick empty-layer actions. The Paint menu can create an empty layer or create one from a Sprite Set, then assigns the selected sprite's matching material sheets to every supported layer channel. The Fill menu can create the current Fill or select any compatible `OverlayDataAsset`. An Overlay-backed Fill adds every compatible logical material channel, uses `alphaMask` (or the first texture's alpha) as common coverage, and carries supported UMA blend modes into the corresponding channel settings. **Rasterize to Paint Layer** in the Fill layer's row menu bakes all generated channels and effective mask into editable pixels and removes the Overlay source relationship.

For a UDIM Fill, **UDIM Sources** provides **Use shared source**, **Override**, or **No contribution** for each tile. Assign a tile overlay and/or per-channel textures with **Texture Channel**; texture assignments take priority. Overrides retain their own source alpha, survive shared edits and document history, and export with their physical tile.

Sprite Sets on ribbons and Flat/Triplanar Fill projections use the Albedo sprite's transparency for every channel. Coverage follows the sprite crop, projection, tiling, rotation, and ribbon flips/joins. Overlay sets share `alphaMask` when supplied, otherwise albedo alpha; partial transparency is applied once and preserves normal-map directions.

## Projection layers

Use **+ Projection** (or **Layer > New Projection Layer**) for a fingernail, tattoo, elbow detail, or another single image placement. Each layer owns one editable world-space projector. Use **Layer Channels & Settings**, just like a Paint layer: **Add Channel**, expand its foldout, and choose its own Texture/Sprite, Overlay, or Color source. Albedo and Normal can be assigned together, with independent source inversion, normal convention, enabled state, opacity, and blend mode. **Remove Channel** removes that map and its options, with Undo available. All channels project through the same placement, size, rotation, depth, wrapping, and fade. Albedo alpha provides the common silhouette (otherwise the first assigned map supplies it). Existing single-image and overlay projections retain their maps when opened and can be edited through these channel controls. A new layer is placed immediately on the target surface and aligned to its normal. Click elsewhere on the model to reposition it and align it to the new normal; no placement mode or extra confirmation is needed.

**Texture Mirroring (All Channels)** exposes **Flip X (Left/Right)** and **Flip Y (Up/Down)**. Use Flip X to turn a right-hand pocket into a left-hand pocket; both flips may be combined. They mirror every channel source and the common source-alpha silhouette, including correcting normal-map directions. Flips follow the projector's local image axes and work with textures, sprites, and overlays in every projection mode. Duplicate or instance the layer for the opposite pocket; linked instances retain independent flip settings. Placement, size, and source assets stay unchanged. Painted layer masks stay in destination UV space.

**Gizmo Size (%)** in Projection properties adjusts all projection handle sizes and hit areas from 25% to 500%, including Move, axes, the rotation ring, and warp points. It defaults to 200% (twice the original size); **Reset** restores that value. The size is remembered as an editor preference and does not change or regenerate the projection.

Outside Edit Warp mode, drag the white center **Move** handle to slide the projection across the model with continuous position and surface-normal alignment, preserving its size and spin. Like click placement, dragging refits Wrapped patches and resets pins. A surface miss retains the last valid placement and resumes when the cursor returns to the target; the whole drag is one Undo step and Escape cancels it. Clicking elsewhere on the model still places the projection. The Scene view also shows **X** and **Y** size handles along the projection plane, a **Z Depth** handle extending into the model, and a rotation ring around the surface normal. Drag around the ring to spin the image in its plane: the grabbed point follows the cursor around the circle, including complete turns and changes of direction. Moving directly toward or away from the center does not rotate the image. Resizing preserves the placement and normal; repositioning preserves size and transports the existing spin to the new normal. The X and Y handles always resize only their own axis, including on older layers saved with aspect lock enabled. **Lock Numeric Aspect** applies only to the Width/Height fields; numeric sizes use world units. **Match Source Aspect** restores the source proportions. The cyan grid and front/back outlines show the projection area and full depth on both sides of the placement plane. Edits replace the previous output across every member of the logical target, including UDIM boundaries. Each click or handle drag is one undo step; Escape cancels the current drag. During a drag, geometry and channel textures are reused and first-surface visibility is rasterized on the GPU for both Planar and Wrapped projections. Feedback uses the full texture and visibility resolution, with the same result on release; devices without floating-point blending retain the CPU visibility fallback. Existing saved projections retain their original centered depth volume until repositioned.

**Planar** projects straight onto the surface. Depth is the maximum distance in front of and behind the clicked plane, so small raised or recessed faces stay covered. The frame shows both limits. Planar projection gathers intersecting polygons, rejects back-facing polygons when Front Faces Only is enabled, and clips the remaining pixels to the footprint and depth volume. **Wrapped** starts with a smooth nine-point patch. **Edit Warp** fits the patch and exposes its surface handles. Drag individual points along the model; Shift-click to pin or unpin a point (orange). Refit and Reset retain pinned points. Choose a 3 x 3, 5 x 5, or 9 x 9 control grid; subdivision preserves the existing shape and matching pins. Reducing the grid removes intermediate controls, with Undo available. **Fit to Surface / Refit** fits unpinned points within the depth volume; partial fits report how many were found or retained. Increase depth if points cannot reach the surface. Turn Edit Warp off to use the existing placement, resize, and rotation controls. Clicking a new location resets pins and fits the patch there. Resizing or rotating transforms the existing patch; use Refit to fit the new footprint. The patch remains fixed in world space when the character changes.

**Cylindrical** wraps an image around a limb or tube. Its axis follows the projection's Y direction and its front touches the clicked surface. Width becomes **Arc Length (X)**; at 360 degrees this is the circumference (radius = width / (2 * pi)). Height and depth retain their world-unit meanings. Adjust **Cylinder Arc** for a partial wrap. All channels share the same cylinder. At 360 degrees, Rectangle edge fade applies at the top and bottom without opening a faded vertical seam; the source image itself must tile to hide its image seam. Ellipse and Alpha Outline retain their source-shaped fades.

**Edge Fade** offers None, Ellipse (circular when width equals height), Rectangle (distance from the border), and Alpha Outline (distance from the source silhouette, including holes). Fade Width and Fade Curve control the transition; Depth Fade softens both depth boundaries, while Angle Fade independently softens the facing limit. Source alpha is applied once. **Front Faces Only**, **Connected Surface Only**, and first-surface visibility are enabled by default. **Project Through** includes hidden surfaces within the volume; disable Connected Surface Only as well when intentionally projecting onto separate mesh pieces. Visibility Quality and Surface Tolerance control sampling accuracy. Alpha Outline measures the silhouette at 50% alpha.

Projection layers support opacity, blend modes, channel controls, effects, painted masks, duplication, undo/redo, document saving and recovery. Normal maps are reoriented into the destination surface's tangent space. **Rasterize to Paint Layer** keeps the generated pixels and mask and removes the editable projector. Exports are ordinary UMA textures and follow the model after export. Material presets retain the world-space definition; when a saved surface region is unavailable, the cached output is preserved until the projection is placed again.

## Clothing detail generators

Use the **+ Projection** or **+ Path** dropdown, then **Garment**, for six families and 32 presets: Wrinkles & Tension Folds; Denim Wash & Garment Wear; Pockets & Garment Panels; Zippers, Closures & Hardware; Distressing & Repairs; Labels, Patches & Prints. Paths additionally offer 16 **Hems & Seams** presets, for 48 path constructions; projections offer 32. Properties uses one **Garment Generator** toggle and grouped **Construction Preset** selector, showing only the selected construction's controls. These native procedural sources share the existing projection placement/warp/flip controls or continuous path ribbon/fade controls. They support coordinated Albedo, AO, Roughness, Metallic, Normal Control height, optional direct Normal, and Custom RGB wear/protection/recess outputs. Relief presets default to Height (Normal Control), which merges with the underlying fabric normal through RNM; wear-only presets leave bump off. Tune Height Strength in the Normal Control channel settings. Direct Normal output uses ordinary layer blending and is opt-in; use one relief output at a time. Saved layers/custom presets retain their explicit choices, while choosing a built-in construction restores its recommended relief outputs. Distances use world units on 3D surfaces and UV units on 2D paths. Grayscale cloth shading preserves the underlying fabric with Normal blending.

All path constructions share a **Ribbon Width** slider and exact numeric field. Switching constructions preserves path placement, width, fades, and assigned image sources, and supports Undo/Redo. **3D Depth** (0–4) and **Relief Shading** (0–3) independently control physical relief and material shading for hems, seams, and non-zipper constructions; both default to 1. Zippers retain their combined depth-and-tone response to 3D Depth, with Relief Shading as an additional multiplier. Wear-only presets and Printed Logo expose shading without a depth control.

Projection wear can read live fold height and seam protection from other layers or groups, including evaluated channel effects and masks. Dependencies update automatically, resolve local UDIM members, survive group duplication/material presets, and retain cached output with diagnostics if missing or circular. Path wear is self-contained. Labels accept an optional logo texture/sprite. Save/Load Garment Generator Preset assets reuse construction settings; Material Presets also carry the source layers and internal links. Documents, recovery, Undo/Redo, and export retain the generated detail. These are texture effects, not garment geometry. See [Clothing detail generators](Documentation/OverlayPainter.md#clothing-detail-generators) for presets, output meanings, and the fold-to-wear workflow.

## Path texture mirroring

Path properties expose **Texture Mirroring (All Channels)** with independent **Flip X (Left/Right)** and **Flip Y (Up/Down)** modes: Off, Every Tile, Alternate, and Random. Alternate flips every second repeat, starting with an unchanged first tile. Random chooses each axis independently at 50%, using the saved **Flip Seed**. Tile/stamp indices are shared across channels and UDIM destinations, and normal-map directions are corrected with the image. Changes support Undo/Redo, Auto Update, saved documents, and recovery.

Ribbon mode mirrors complete tiles, including Beginning/End sources, in 2D and 3D. Stamps/Continuous mirror each Texture/Sprite stamp; Overlay sources keep destination UV mapping in those modes. Filled paths mirror their boundary stamps. Geometry, fades, and destination masks retain their coordinates. Existing paths default to Off on both axes.

## Ribbon join crossfades

**Path Properties > Ribbon Tile Joins > Crossfade Joins** overlaps each outgoing image with the next and uses complementary smooth fade weights. **Join Overlap (%)** controls the total blend width around each join, from 0 to 100% of fitted tile spacing (20% initially; crossfading defaults off). Opaque images retain their opacity; transparent colors are alpha-weighted and normal vectors are normalized. Each tile retains its own alternate/random flips, shared across channels.

The images extend into the overlap while tile count, spacing, and ribbon geometry stay fixed. Open Beginning/End images blend into their neighbors, and closed paths crossfade the last tile into the first. Side and whole-path endpoint fades remain independent. The settings support save/recovery, Undo/Redo, and Auto Update in both 2D and 3D Ribbon paths.

## Composable masks and smart masks

Select a layer/group mask and open **Mask Effects & Smart Masks** in Properties, or use the layer's **fx** popup. Effects evaluate from top to bottom. Each has enablement, opacity, blend mode, independent parameters, duplication, and up/down ordering. The result is shared by channel compositing, mask previews, linked layers, and export. Legacy noise/texture masks retain their appearance; **Convert Legacy Effects to Stack** makes those inputs reorderable.

The 44 effect kinds include:

- Inputs and patterns: Fill, Texture (luminance/R/G/B/alpha), Painted Mask, Layer Reference, Noise, Turbulence, Voronoi, Cells, Gradient, Radial Gradient, Stripes, Checker, Dots.
- Adjustments: Invert, Levels, Curves, Brightness/Contrast, Gamma, Threshold with softness, Posterize, Clamp, Remap, Smoothstep.
- Spatial filters: Gaussian Blur, Directional Blur, Sharpen, High Pass, Dilate, Erode, exterior Outline, Edge Detect, signed Distance, Feather, UV Transform, noise Warp. Filter radii are texture pixels; spatial passes use half-float GPU intermediates.
- Mesh inputs/generators: Curvature, Ambient Occlusion, Thickness, World Normal, World Position, Mesh ID, Edge Wear, Cavity Dirt, Dust. Assign **Map Override** to use an imported mesh map. Built-in AO and thickness remain quick estimates, not ray-traced/high-to-low bakes. Mesh ID defaults to triangle ID (Red); Green selects surface ID, Blue selects UV-island ID.

For non-destructive hand-painted exclusions, disable **Start From Painted Mask**, generate the mask with procedural entries, then add **Painted Mask** with Multiply at the end. Painting the existing mask thumbnail changes only this original raster input. Use separate painted layers and **Layer Reference** inputs when you need several independent painted sources. Reference entries can also read Plugin layers, named anchors, channel components, or another mask. Missing/circular dependencies retain cached inputs and show a diagnostic; saved documents preserve these caches. Logical UDIM references resolve to the corresponding local tile. Duplicated groups and material presets remap their internal references.

Smart-mask examples include cavity dirt, edge wear, dust, position gradient, grunge, soft border, spots, and scratches. **Save Recipe...** creates a reusable Smart Mask asset and embeds texture inputs. **Replace Effects** or **Append Effects** loads its recipe without replacing the destination's painted corrections. Recipes with layer references still require the source layers; complete material presets can carry those layers together. Append obeys the stored blend settings, so a Replace input replaces the accumulated result at that point. Mask copy/paste, Undo/Redo, recovery, and documents retain the stack.

## Camera-space painting stencil

In the Brush window, open **PAINTING STENCIL**, assign an image, choose its mask channel, and enable it. The stencil stays fixed to the current 3D view and limits coverage for every painted channel, including layer masks, erase, blur, and normal touch-up. The preview opacity changes only the guide. Brush color/channel sources still supply the paint.

Toggle **Edit Stencil in 3D View**: drag to move; Shift-drag around its center to rotate; Ctrl-drag vertically to scale. Numeric center/size use viewport fractions. **Center and Match Image Aspect** restores image proportions. Escape cancels a drag or exits stencil editing; turn editing off to paint. Edits are undoable. Strokes snapshot their stencil definition and camera transform, and completed pixels survive save/reopen normally. The stencil intentionally applies to interactive 3D brush painting, not the 2D canvas or procedural paths. Coverage is projected once per surface/resolution per stroke and reused across channels.

## Painting

- Channels: Albedo, Normal, Metallic, Roughness, Ambient Occlusion, Emission, Skin Color Mask,
  Thickness, Detail Mask, Normal Control, and a custom channel. Normal Control is an automatically
  available painter-owned grayscale height modifier whenever Normal is supported: neutral gray is
  unchanged, dark recesses, and light raises. It is combined into the effective normal for both 3D
  preview and export, but is never bound to the material or exported as a standalone texture. The
  full toolbar automatically becomes a channel dropdown when a material exposes more than seven
  logical channels.
- Tools: paint, erase, blur, smear, clone, dodge, burn, normal touchup, and a brush-plugin mode.
- **Cap Update Per Stroke** accumulates each target texel against its stroke-start color. Hardness and the brush falloff define the maximum coverage at that location, while Flow controls how quickly paint builds toward it. Repeated stamps therefore preserve a Photoshop-style soft perimeter instead of filling every grazed edge to 100%; a pass closer to the brush center can still increase that texel's coverage.
- Hardness attenuates both color and stored layer alpha. Source alpha is combined with brush coverage once using source-over math, so partially transparent paint is not unintentionally squared.
- 3D strokes and world-authored paths are resampled by cumulative world-space arc length. The 2D canvas paints directly in normalized UV space and resamples on that texture plane; it never round-trips ordinary brush stamps through mesh triangles. Hold **Shift** when beginning a freehand stroke to lock it horizontally or vertically on the active view plane; the first meaningful drag delta chooses the axis for the complete stroke. Spacing remainder carries across editor events, and pressure, time, direction, and the appropriate world or UV anchors are retained in persistent stroke records.
- Stabilization, direction filtering, pressure-to-flow, pressure-to-size, projection depth, surface-normal angle, and backface controls are available with the brush settings. **Follow Stroke** rotates directional stamps along the filtered path.
- Brushes: circle, square, or texture stamp with size, hardness, flow, spacing, rotation, blend mode, and optional global-X mirroring. Splatter supports an adjustable offset radius and optional **Random Strength**, which independently varies each scattered stamp from zero to the current paint strength. Brush assets and per-Paint/Path snapshots retain all randomization settings.
- **Path Properties > Fading** controls **Side Fade (%)**, **Start Fade (%)**, and **End Fade (%)**. Ribbon Side Fade reaches the centerline at **100%**; **200%** spans the full width and fades the center too. Separate **Side Curve**, **Start Curve**, and **End Curve** fields control opacity: the curve's left end is the interior, its right end is the side edge or path endpoint, and height runs from 0 (transparent) to 1 (opaque). Lower the curve to remove more backing or reduce opacity throughout the fade; **Reset** restores the smooth profile. An enabled **Edge Fade** effect supplies the same side distance/curve controls plus **Fade Ramp (%)** in both the effect popup and Path properties, independent of the displayed channel. Without that effect, saved brush hardness supplies the first 100% of side fade; older paths retain their appearance. Endpoint distances use the complete path length (never individual image tiles), extend to 200%, and are disabled for closed paths. Zero disables that fade. Endpoint curves also work for non-ribbon paths; their side control remains brush softness. These settings save with the path, regenerate in both 2D and 3D, and support Undo/Redo. Source alpha is preserved.
- Every Paint, Fill, Path, Projection, Plugin, or Group layer can own one editable grayscale layer mask. Add a black or white mask from the layer-row menu, click its thumbnail to enter **Layer Mask mode**, and paint it in either the 2D or 3D view with the regular brush tools. Press **Escape** to leave Layer Mask mode; Overlay Painter consumes that key in its Layers, Brush, 2D, and dedicated compact Scene views so Unity does not close the painting stage or open the save prompt. If a mask stroke is still active, its painted portion is committed before the mode exits. An active Geometry Fill keeps first priority, so the first Escape cancels that fill mode and a second exits Layer Mask mode. Mask painting is deliberately channel-free and grayscale-only: **Mask Value** selects a scalar from black (hidden) to white (visible), and texture, sprite, material-channel, and OverlayData paint sources are unavailable. Both views display a Layer Mask label; **Solo Mask** previews the effective mask on the model. **Layer Mask Noise** and **Layer Mask Texture Overlay** provide non-destructive texture variation without changing the mask brush source. **Fill Polygon** and **Fill UV Island** are ordinary paint operations on Paint layers and masks. Groups apply opacity, blend mode, and their mask once to the isolated child composite.
- Slot targets: one or more reconstructed UMA slots can be selected together. In 3D, brush application is based on the full world-space footprint rather than only the center ray: every selected slot and UV island intersected by the brush receives a projected stamp, including slots backed by different materials before the cursor center crosses their border. A linked stroke synchronizes its channel sources across every physical member, repairs stale empty Texture-source metadata from the valid stroke source, and refuses to start with a named error if any selected member still lacks a writable raster target. Target-filtered raycasts ignore closer unselected surfaces, the Backfaces setting applies to both hover and projection queries, mouse capture lasts for the complete gesture, and a bounded 0.1-second/16-pixel grace tolerates an isolated seam miss without bridging a broad empty region. Per-triangle slot ownership excludes unselected geometry, and a cached spatial triangle grid keeps footprint queries local. In 2D, the active texture set is painted directly wherever the normalized-UV brush lies; ordinary brush movement and rasterization do not query or clip against the mesh.
- Geometry clipping: projected 3D contacts use a cached per-texel UV geometry selector so rectangular update tiles cannot leak into unrelated polygons. The dedicated **Polygon Fill** and **UV Island Fill** buttons intentionally resolve mesh ownership in both views, including Layer Mask mode; ordinary 2D brush strokes do not.
- Surface paths: click **Create Spline Layer** to create and activate a dedicated layer, then choose **Spline Space: 2D Texture** or **3D Surface** in Properties. A path has exactly one editing and raster domain; input from the other view is ignored instead of silently converting the path. New paths default to 3D Surface. For a 3D path, **Shift+Click** the model to append a surface node and use the Scene view to select, insert, move, and adjust controls. It interpolates in world space, remains continuous across UV seams and UDIM tiles, and resolves UVs from projected surface samples only while rasterizing. Projection prefers the connected polygon strip containing each control, so a long strap or belt segment does not fall onto a nearby disconnected layer of the same mesh. Separate reconstructed surfaces remain eligible at real slot and UDIM transitions. A 2D path is authored and rasterized directly in normalized texture space without model-overlap ambiguity. Selecting one of its points in the 2D canvas exposes only that point's complete orange/green/blue adjustment setup on the model as a positioning aid; the 3D view does not draw or convert the 2D spline. Both views show green incoming/outgoing handles for reshaping the selected Bezier point and a distinct blue perpendicular handle for changing its width percentage directly. The point remains selected after moving or adjusting a handle; deleting it selects a surviving neighbor or clears selection when no points remain. Both 2D and 3D ribbons use the same intrinsic across/along renderer, so edge-specific strokes, shadows, glows, bevels, stitches, and edge fade behave consistently in either domain. **Ctrl+Click** (**Command+Click** on macOS) within 8 screen pixels of the editable spline splits the nearest segment; clicking farther away does not insert. Nodes support insert/delete, multi-select dynamics, copy/paste, reverse, corner/smooth/broken/custom/straight tangents, and per-point pressure, width percentage, flow, roll, color, and offset. Right-click a point in either editing view for linear handles, deletion, and width presets. Apply as stamps, a gap-free continuous stroke, complete source-image ribbon tiles fitted edge-to-edge, or a closed fill, with Follow Path/fixed-axis orientation, caps, mirroring, radial symmetry, and any paint/erase/blur/smear/normal-touchup tool.

**Hems & Seams constructions:** **+ Path > Garment > Hems & Seams** adds a procedural ribbon with one of 16 constructions, including denim chainstitched hems, flat/mock-felled and French seams, piping, overlock, coverstitch, blind/rolled/raw hems, topstitching, and bartacks. Existing paths select them through **Garment Generator > Construction Preset**; saved hem/seam layers use the same controls. Cloth profile, roping, slant, seeded irregularity, stitch puckering, fraying, grayscale recess shading, bump wear, and protected seam/newness are independently adjustable. Up to eight colored stitch rows support seven stitch patterns, position, size, spacing, phase, and relief. **3D Depth** scales cloth and thread height, while **Relief Shading** independently adjusts their contact shading. Generated Albedo preserves the underlying fabric through straight-alpha grayscale adjustments plus colored thread; default Normal Control height plus AO and Roughness, and optional direct Normal and Custom RGB wear/protection/recess masks share the same intrinsic ribbon coordinates. Closed paths fit whole cycles, Normal output uses the destination tangent frame, and construction mirroring corrects the slope. Path fades, model undo, persistence, Auto Update, and logical/UDIM peers remain available. It generates texture relief, not geometry displacement. See the main guide's **Hem / Seam generator** section for presets, settings, and sewing references.

When an enabled Path layer is active, the Scene view shows a separate **Overlay Painter Path** toolbar. Disabling the layer hides its raster result and all 2D/3D spline authoring overlays; re-enable it to edit. **Standard** mode provides topology, anchor movement, curve handles, and width handles; **Move** exposes only selectable/movable anchors; **Adjust** locks anchor positions and exposes curve and width adjustment. These modes constrain direct viewport gestures only: Closed Path and every point/path action in the toolbar remain available in Standard, Move, and Adjust. The toolbar owns those commands so they are not duplicated in Properties. **Auto Update** is enabled for new and legacy paths and rebuilds after edits using the coalesced GPU path pipeline. Disable it to make any number of topology, position, tangent, or width edits without rerasterizing; **Update** explicitly rebuilds every affected channel and path effect when ready. The edit mode and Auto Update choice are stored per Path layer.

3D spline controls and samples remain surface-projected. A 2D spline's raster and stored curve stay on the texture plane; only the selected point's temporary Scene-view adjustment handles are projected onto the model.

Stroke kernels copy, compose, and repack only dirty tiles, including each filter's required halo. Every
raw freehand input event queues its already-accepted normal and mirrored contacts, preserves their
original order, and submits them in bounded batches grouped by destination 128-pixel tile. Projected
batch stamps carry their own triangle UVs and boundary ownership, so this optimization does not alter
all-member UDIM queries, slot selection, seam padding, or the shared-edge rules. Compositing,
`TextureChanged`, and preview packing are deferred until that input event finishes, then run once per
dirty target tile instead of once per contact. Paint kernels use synchronized source/destination
ping-pong so the same path remains portable to GLES3, and spline/path
samples use the same bounded GPU path. Capped stroke coverage is allocated as sparse 128-pixel tiles
instead of full-size float textures. When compute shaders are unavailable or a configured memory
budget would be exceeded, the same ordered samples run through the existing compute or sparse CPU
fallback.

Undo/redo stores only touched tiles. A target/history-tile pair is captured immediately before its
first write and only once for the complete stroke, including a rewind/replay; later contacts reuse that
original capture. Before/after pixels are captured through asynchronous GPU readback where supported,
kept in the target's exact graphics format, and losslessly Deflate-compressed. Undo work and memory
therefore scale with painted area rather than total texture size. The **Performance & Memory** panel
exposes rolling preview p95/maximum latency, dirty copy/compose counts, compute/fallback counts, undo
and active-stroke memory, configurable budgets, and a resource-baseline leak check.

For focused painting analysis, enable **Stroke Diagnostics** in **Performance & Memory** and click
**Capture Next Stroke**. Diagnostics are disabled by default and retain no per-stroke samples until a
capture is queued. The resulting copyable report compares early/middle/late input latency and breaks
the stroke into input raycasting, sample projection, spatial contact discovery, per-contact preparation,
history capture, raster submission, compositing, preview binding, and finalization. It also records
normal/mirrored footprint counts, spatial cells and triangle candidates, accepted contacts, raster target
visits, compute/fallback counts, dirty pixels, history/coverage working sets, and stored stroke/contact
state. Capture-thread managed allocations and nested phase allocation totals expose list, dictionary, and
GC pressure. Matching `OverlayPainter.Stroke.*` markers appear in the Unity Profiler. Reported phase time
is main-thread CPU submission time; use the GPU Profiler alongside it to distinguish GPU execution or
queue pressure. Disable **Stroke Diagnostics** at any time to remove its hot-path collection immediately.

In the 3D view, brush size is evaluated through a per-triangle UV-to-world metric rather than a scalar UV radius. Circle, square, and stamp brushes therefore retain their world-space dimensions across slot seams with different UV density, rotation, or anisotropic scaling; conservative UV bounds keep the complete projected footprint inside the updated tile. In the 2D view, the same size value is a stable normalized-UV radius, so the cursor and painted footprint remain fixed while moving across triangles of any world-space size.

## Normal touchup

On stage initialization, each material mesh is rasterized in UV space to create interpolated vertex-normal and tangent maps on the GPU when supported, with a deterministic CPU fallback. Coincident vertices with discontinuous UVs create a seam lookup map. These maps are reference-counted and shared by a hash that includes mesh positions, normals, tangents, topology, UVs, dimensions, and seam width. An on-demand, bounded-resolution procedural cache supplies world position, world normal, signed curvature, concavity accessibility, thickness, and triangle/surface/island ID maps to masks and model plugins without adding startup cost to every material. Signed curvature uses 0.5 for flat, values below 0.5 for concave regions, and values above 0.5 for convex regions. Long map builds accept cancellation and progress reporting. The normal-touchup kernel converts the painted tangent-space normal to model space, bends it toward the interpolated vertex normal, optionally blends its seam partner, then converts it back to tangent space. Ordinary normal painting is vector-aware on both GPU and CPU, and export supports OpenGL or DirectX green-channel convention.

## Layers, documents, and persistence

Grayscale channels in the 2D window provide a **Brightness / Contrast Curve**. Its horizontal axis is the original grayscale value and its vertical axis is the amount of Brightness and Contrast applied. The default diagonal leaves black untouched and progressively increases the adjustment toward white. The curve is stored per channel and participates in Undo/Redo, preview, document persistence, and export.

On a Fill layer, **Use Transform For All Channels** appears on the first channel. It makes that channel the master for X/Y tiling, X/Y offset, and rotation, immediately synchronizes the remaining channels, and locks their transform controls until sharing is disabled.

Paint, fill, spline, Plugin, and group layers are independent transparent surfaces composited from bottom to top on the GPU. Layers can be hidden, reordered, renamed, duplicated, merged, deleted, and adjusted globally or per channel with visibility, paint lock, opacity, and blend controls. Plugin layers expose cached output channels rather than painting/source controls and support Merge Down using their current cached result. Each authored channel card owns its source and includes an undoable Remove operation. Texture and overlay sources on Fill layers provide independent X/Y tiling, X/Y offset, and rotation controls for both Flat and Triplanar projection. Paint and spline channels additionally expose Channel Paint Strength for scaling newly authored pixels; Fill layers do not use or show it. The 2D window provides non-destructive Brightness, Contrast, Hue, Vibrance, Saturation, and RGB Color Balance for the currently displayed channel; values persist per channel, participate in Undo/Redo, and feed both preview and export. Chromatic controls are disabled for grayscale data and all image adjustments are disabled for encoded normal vectors. The layer-row **fx** button opens an ordered, multi-instance stack of non-destructive Stroke, Inner/Outer Shadow, Inner/Outer Glow, Color Overlay, Texture Overlay, Image Adjustments, ribbon-specific effects, and mask-only effects when a mask is present. Effects can target only channels authored by the layer. **Image Adjustments** changes Saturation, Brightness, Contrast, and Hue on one selected channel, with an independent Amount control; Hue and Saturation are disabled for grayscale channels. Layer/channel opacity and masks are applied once to the isolated paint-plus-effects result, so translucent art and falloffs do not become solid through repeated passes. Widths and shadow offsets are measured in destination pixels, shadow/glow falloff uses an editable curve, and every conventional effect has an independent Level control. **Texture Overlay** clips two optional repeating textures to existing coverage; each source has independent X/Y destination-UV tiling, offset, center rotation, blend mode, opacity, and RGBA color multiplier. Texture 1 is combined first and Texture 2 second. On a ribbon, effect instances are evaluated as ordered projection passes from the traveler's long-edge coordinates. Inner/Outer Shadow and Inner/Outer Glow can target **Left**, **Right**, or **Both** edges without wrapping across beginning/end caps. **Bevel Edge** assigns a light or dark treatment and offset to either long edge. **Procedural Stitch** generates single or double dashed thread rows. Ribbon path properties can replace the first and final complete tiles with separate Beginning/End textures or sprites; closed ribbons ignore them. Group rows use a folder icon and support nested groups. Drag a layer or complete group subtree onto a folder, click to collapse/expand, or select a group before creating a child. Children remain contiguous; Remove from Group moves the complete subtree above its former parent. Group visibility, opacity, blend, and mask apply once to the isolated descendant composite. Duplicating a group deep-copies every descendant. Deleting a group warns and deletes every descendant. The Merge menu offers **Merge Down**, **Merge Group to Paint Layer**, and **Merge Selected**. Ctrl/Cmd-click each desired row to mark it for merging without changing the active layer; a successful merge activates the new Paint layer. Merge Selected combines adjacent siblings, including complete group subtrees, in stack order. A single group retains its outer opacity, blend, and evaluated editable mask; child settings become pixels. Multi-layer merges require Normal-blend roots, and unsupported backdrop-dependent settings or external references report a reason. All channels and linked UDIM peers merge in one undoable operation. Clear, Escape in the Layers panel, or an ordinary row click clears merge marks. Structural edits, channel edits, masks, effects, and channel adjustments participate in Undo/Redo, with continuous slider gestures coalesced into one history step.

Reusable **Material Preset** assets save a whole layer stack, one layer, or a complete group subtree, including hierarchy, all authored channels, compressed raster pixels, Fill projections, masks, effects, paths, plugin ids/versions, parameters, and cached procedural output. Use **File > Material Preset**, either add-layer dropdown, or a layer row's **Preset** menu to save or apply one. Application targets the currently selected logical paint target, maps semantic channels supported by each destination material, scales cached pixels to the working resolution, warns before transferring UV-dependent content to a different layout, and creates a named wrapper group. Available layer and mask generators rerun sequentially from the bottom of the saved stack to the top so each filter sees the regenerated composite below it. Missing plugins retain their cached result and remain stale. Cancellation or generator failure rolls back the complete application, and a successful application is one Undo/Redo step. Applied layers are independent copies but retain the source preset id and revision for provenance.

Select a Material Preset asset and click **Package** in its Inspector to create a single distributable `.asset`. Packaging embeds copies of the thumbnail, textures, sprites, OverlayDataAssets, brush presets, UMA materials, Unity materials, fonts, and externalized raster payloads used by the stack, then rewrites the preset to those embedded copies. Plugin implementations and shaders remain project prerequisites and are listed on the packaged asset. A packaged preset appears in the same Material Preset picker and applies in Overlay Painter exactly like a regular preset; the original loose texture assets are not required.

Opening the stage starts a temporary session without changing the character, scene, recipe, source overlay, or source textures. After an edit, recovery creates `painter_recovery.asset` and a sibling `painter_recovery Data` folder in the recovery folder configured under **Project Settings > UMA > Overlay Painter**. The default folder is `Assets/UMAProjectData/OverlayPainter/Recovery`. **Enable Automatic Recovery** defaults on, **Recovery Idle Delay** defaults to 120 seconds after the most recent edit, and **Minimum Save Interval** defaults to 300 seconds between completed background saves. The same scheduler autosaves modified permanent documents. Disable automatic recovery to stop periodic background saves; manual Save and the unsaved-changes close prompt remain available. The next compatible ordinary launch offers Recover, Discard, and Cancel choices. When a saved document was opened explicitly while compatible recovery exists, **Open `<document>`** is the default choice and discards the older recovery; **Recover Instead** is available but never silently replaces the requested document. **Save As** creates a permanent, versioned `TexturePaintDocument` wherever the user chooses below `Assets`, with compressed pixel blobs in a sibling `<Document Name> Data` folder. Double-click a compatible document asset in the Project window to open it directly, or use **File > Load Document** in an active Overlay Painter stage. Later recovery and document saves reuse unchanged content-addressed data assets and write only changed texture targets. GPU capture uses asynchronous readback and compression runs away from the editor thread; Unity's final asset import is synchronous and can still cause a short editor hitch. Closing while the document is modified or a matching recovery asset exists offers **Save**, **Discard**, and **Cancel**. Save commits the project document before deleting recovery, Discard deletes recovery and closes without saving, and Cancel leaves both the editor session and recovery untouched. If a background autosave is already running when Close is requested, the window closes immediately and that in-flight save becomes the final close-save; the stage exits automatically after its durable commit. Export completion restarts the configured autosave debounce so a long asset import cannot unexpectedly begin a document capture while the export and painter windows are being closed.

For an active avatar, generated material metadata is used only to locate source slots, their original overlay stacks, and the material shader contract. Each generated material surface is separated back into native slot surfaces, UVs are restored from the corresponding `SlotDataAsset`, and channel composites are rebuilt from the original overlays at the native base-texture resolution. Overlay Painter never uses `GeneratedMaterial.resultingAtlasList` as editable source data; the generated atlas may already be resized, filtered, and normal-swizzled and is therefore unsuitable for lossless authoring.

The document losslessly persists editable base pixels, layer pixels, masks, splines, per-layer source/brush settings, and workspace state. Surfaces bind through stable material/slot/mesh identities rather than temporary reconstruction indexes. UMA's random `_Genb_<number>` generated-material nonce is excluded from new surface identities. Existing documents whose legacy ids include that nonce rebind through a conservative score of slot ownership, UV/topology fingerprints, UMA material, and the saved renderer/submesh location; an unchanged UV layout restores raster layers and masks exactly even when regenerated triangle ordering differs. Export reads either the live flattened composite or a temporary authored-layers-only composite, according to the selected export mode, without saving or changing the document, avatar, recipe, or scene. Recovery assets are temporary project content and should not be shipped. To keep the default recovery location local, add both `/Assets/UMA/Temp/` and `/Assets/UMA/Temp.meta` to the project's source-control ignore file. If the recovery folder setting is changed, ignore the configured folder and its `.meta` file instead.

Only one `painter_recovery.asset` is active in the configured folder. It records its source context and is offered only to a matching Overlay Painter launch. A later temporary session can replace recovery belonging to another context. **Save As** creates the permanent editable document; deleting or ignoring the recovery folder does not remove saved documents or exported overlays/textures.

Shader-aware material targets compile the active URP or HDRP material selected by the `UMAMaterial` into one capability descriptor before the stage opens. That descriptor validates shader properties, RGBA meanings, source textures, formats, color space, importer rules, and GPU packing support, then drives logical-channel creation, preview binding, and export. Packed maps are unpacked into their declared logical channels and repacked into their documented physical layouts. Smoothness is inverted into the Roughness editing convention. Skin Color Mask remains RGBA color data, while Thickness and Detail Mask are editable scalar data. Linear data remains linear, color data remains sRGB, and albedo export dilates RGB beyond transparent UV borders to prevent mip seams. Built-in/Standard is not part of the certified workflow.

Normal Control is document-owned auxiliary data and deliberately does not participate in material
capability discovery or physical packing as an independent channel. A matching-resolution neutral
gray target is added automatically beside every logical Normal target. The selected Normal preview,
group preview, physical material binding, flattened bake, and authored-overlay bake all consume the
same derived effective normal. Authored-overlay export derives a flat-relative normal delta and
includes its gradient coverage in `OverlayDataAsset.alphaMask`. Documents and recovery snapshots
retain its pixels and per-layer sources. **Height Strength** is stored independently on each
layer's Normal Control channel, so changing a paint, fill, or path layer does not rescale other
height contributions. Sample radius and height inversion remain shared conversion settings for the
texture target.

Each `UMAMaterial.MaterialChannel` has editor-only **Overlay Painter Channel Layout** and **Physical Output / Import** sections. Automatic mode follows known URP/HDRP conventions and material settings; Custom mode provides explicit RGBA mappings, PNG/EXR encoding, importer type, color space, alpha, normal convention, mipmap, compression, filtering, anisotropy, maximum-size controls, and optional TextureImporter platform overrides. The export window previews the resolved contract and actionable diagnostics before writing files.

**Export Textures & UMA Assets...** opens a dockable, descriptor-driven export window organized into Content, Naming and Location, Texture Output, Advanced, optional Material Contract Details, and the resolved output plan. Enter the required **Export Identifier** and choose **Flattened Composite** or **Runtime Overlay (Transparent)**. Flattened Composite is the default and exports the reconstructed character texture plus visible painter layers. Runtime Overlay excludes the reconstructed base and direct base painting, composites only visible authored layers/groups into temporary transparent textures, exports only material channels with authored content, generates a grayscale RGBA coverage texture, and assigns that texture to `OverlayDataAsset.alphaMask` for UMA runtime blending. The coverage mask is the union of visible authored channel alpha after layer opacity, group opacity, masks, and effects. Runtime Overlay always creates separate assets and cannot overwrite a source overlay. Release export writes physical textures in `UMAMaterial.MaterialChannel` order using each channel's descriptor for RGBA packing, semantic conversion, PNG/EXR encoding, color space, normal convention, and importer settings. Names use the persistent source texture stem when available, fall back to the slot/group and material-channel name, and append the UDIM tile number for tile outputs. No export-template asset is required: session defaults provide current/all-material scope, overwrite/fail/versioned conflict policy, native or fixed resolution, and edge padding. When the Addressables package and `UMA_ADDRESSABLES` scripting define are both enabled, **Mark Addressable** can also register the exported assets in the default group. The core Overlay Painter assemblies do not reference Addressables, so projects without that optional package compile and export normally. Use **Save Overrides as Template** only when those output choices should be reused. Albedo padding is performed on the GPU, preserves the original alpha, and reports/cancels between passes even for large outputs.

Generated-character export reconstructs the source from the character's original slot and overlay
textures at their native working resolution; it never reads the UMA generated atlas. Normal output
is rebuilt as ordinary tangent-space RGB from logical vector data before the requested OpenGL or
DirectX convention and importer settings are applied.

Export is a transaction: every texture is baked and encoded into staging before commit, existing files/importers/UMA assets are snapshotted, and newly created files, overlays, UMA index entries, and—when enabled—Addressables entries are rolled back together on cancellation or failure. A new recipe-ready `OverlayDataAsset` is created and registered with `UMAAssetIndexer` for each ordinary slot or UDIM tile, and library lookup is verified before success is reported. Export never creates material overrides, updates a recipe/avatar, saves the paint document, or stores history in it. **Overwrite Source Overlay** is a separate destructive mode available only for persistent source overlays; it previews every affected asset, requires confirmation, and restores backups on failure.

Documents fingerprint geometry, topology, UVs, and material bindings independently. Stable matches restore exactly; compatible material or reconstruction changes rebind automatically. Rebinding prefers exact UV plus topology, then unchanged UV, matching topology, and finally a matching saved renderer/submesh backed by compatible material evidence; slot overlap is always required. When topology still matches but UVs change, surface-anchored strokes and spline paths are retained for rerasterization while stale raster pixels are preserved as explicitly orphaned document content. Layer masks retain their base value, grayscale paint value, and procedural effects but reset stale pixel-space painting to the base value. Removed or incompatible surfaces are reported in the export window instead of being silently discarded or painted onto the wrong mesh.

## Live references and linked instances

Open **Properties > Active Layer > References and Instances** to give a layer an **Anchor Name**. **Reference This Layer** creates a live Reference layer. Choose its source channel and read color, alpha, luminance, an individual RGB component, or the source mask. Scalar reads become coverage for the reference tint. Source effects, channel opacity, visibility, and masks are evaluated before the reference. Group references isolate the group's authored output from the base texture.

Every layer also has a **Live Mask Source**. Its result multiplies the layer's painted/procedural mask. References update in dependency order; circular or missing references show a diagnostic and retain their cached output. Linked UDIM members resolve to their corresponding local source member. Cross-target references explicitly use the selected source surface. Saved documents retain cached reference pixels and masks, so a missing source can be repaired without discarding the last usable result. Internal links follow duplicated groups and material presets.

**Create Instance** shares source content. Fill instances retain their own UV scale, offset, and rotation; Projection instances retain their own world placement, size, depth, flips, and wrapped patch. Paint, Path, Plugin, and Group instances read the source's evaluated output in UV space. Each instance keeps its own layer opacity and painted mask. **Make Independent** removes dependencies while preserving the current result. Downstream Plugin layers and procedural masks automatically regenerate when their linked inputs change; this derived work does not add pixel-history entries. Save and export wait for those updates to finish.

Source pickers identify material, slot/tile, stack position, and anchor name; source and output channel menus show supported channels. Automatic procedural refresh tracks the full stack below each linked generator and preserves the active layer and existing undo targets. Save and export wait for active gestures and pending linked output before taking their snapshot.

## Selections and reusable regions

**Properties > Selection** provides rectangle and freehand lasso selection in both the UV canvas and Scene view. Choose **Material** or **UV Island** to pick geometry under the cursor. Material selection uses the reconstructed material surface/UDIM member. **Combine** supports Replace, Add, Subtract, and Intersect. Scene selection respects occlusion unless **Select Through** is enabled. Its screen-space shape and visibility are rasterized at 512 and 1024 pixels respectively, then projected into each target's native UV resolution.

Selections constrain brush tools, geometry fills, and ribbon/path painting, including layer-mask painting. They do not change existing pixels or continuously clip Fill/Projection layers. Use **Selection to Layer Mask** to apply a region to existing layer content. Grow/shrink and feather operate in texture pixels; invert, clear, and clear-all are available. **Save Region** stores a named region for the current material/tile; click its name to restore it. Active and saved regions persist in documents and recovery snapshots. UV layout changes invalidate UV-space regions. A multi-tile Scene selection is one undo action. Use **Return to Painting**, press Escape in the viewport, or select a brush tool to leave selection mode. The selection remains active until cleared. A Scene-view reminder shows when selection limits painting, and **Clear All Selections** clears every tile even when the current tile is unrestricted. A click without a drag leaves the previous selection intact. If stored selection data is damaged, the editor reports the problem and blocks painting until you clear or replace that selection. With no existing selection, Subtract removes coverage from the unrestricted tile; Add and Intersect start with the drawn region.

## Layer symmetry

Each layer saves its own X/Y/Z mirror planes, origin, rotation, and radial copies under **Properties > Symmetry**. New layers start with symmetry off. The Scene view X mirror button directly controls the selected layer's **Mirror X** option and enables symmetry when turning X on. Changes support Undo/Redo; paths rebuild through Auto Update (or Apply when Auto Update is off). Paint layers use symmetry for new strokes. Older documents migrate their effective settings, so hidden brush mirror flags cannot override the layer's controls. UV symmetry uses the texture center plus the XY origin offset, Z rotation, and radial rotation about the UV plane normal. Reflections preserve image orientation.

For a placed Projection layer, **Create Symmetry Instances** makes separate linked layers at the symmetric placements in one undoable operation. If any target cannot be generated, the stack is left unchanged. Each remains one editable, world-fixed projection, including wrapped control points. Later symmetry-frame edits affect new placements; existing instances retain their independently editable transforms. Edit the source projection to update shared imagery and material settings, or make an instance independent.

## Extension points

- `TextureStore` owns material/channel targets and ordered layers.
- `PaintingEngine` owns stroke dispatch, CPU fallbacks, and history.
- Reusable regions constrain painting independently of editable layer masks; live references supply layer content and mask dependencies.
- `MeshReconstructor` provides per-material meshes, colliders, triangle islands, and mirror raycasts.
- `TexturePaintStageController` is editor-UI agnostic and can be driven by another tool or custom stage.
